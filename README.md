# sz-diag

Система удалённой диагностики клиентских машин в сервисном центре по номеру **СЗ**
(сервисной заявки, напр. `159873`).

Claude работает на чистом сервисном боксе и дотягивается до клиентских машин по SSH,
не устанавливаясь на них. Агент на клиенте временно открывает SSH-доступ и регистрируется
под номером СЗ; центральный hub держит маппинг `СЗ → IP`, а CLI показывает, какие СЗ
онлайн. Весь доступ на клиенте временный и **откатывается без следов** при закрытии СЗ.

**Модель угроз:** клиентская машина — наименее доверенное устройство, часто заражена.
Рабочий токен на неё не заезжает; диагностика идёт по сети (SSH).

## Что уже работает

- **Агент** на клиенте открывает SSH через портативный sshd **под SYSTEM** (транзиентная
  scheduled task — нужен `SeTcbPrivilege` для logon-token; свои host-ключи каждую сессию,
  без системной службы OpenSSH и Windows Update), шлёт heartbeat, по команде гоняет
  тест-раннер и заливает отчёт. Доступ откатывается по флагам (клавиша `C` / команда `close`
  с хоста / watchdog по таймауту).
- **Hub + CLI** на хосте: реестр онлайн-СЗ, история в SQLite, `szcli`:
  - обзор сессии — `watch` (по умолчанию), `list`, `target`, `close`;
  - диагностика — `diag run <СЗ> [секции]`, `reboots` (таймлайн вырубонов: когда, сколько
    продержалась, чем была занята), `maintenance` (пометить «гасили руками», чтобы событие
    не считалось дефектом);
  - работа на клиенте — `exec` (ad-hoc PowerShell через агента, `--detach` для длинных),
    `push`/`pull` (доставка инструментов и забор файлов через hub), `client info`/`cleanup`;
  - нагрузка — `sensors start|status|stop|report` (CSV 1 строка/период, переживает вырубон;
    отчёт говорит, **сколько времени нагрузка реально держалась**);
  - обслуживание — `freeze`/`unfreeze` (Windows Update на время сессии), `agent set|restart`,
    `kb record|summary|search|doctor`, `hw import|update|resolve`.
- **RunDiag** — `szcli diag run <СЗ> [секции]` гоняет на агенте курируемый набор read-only
  проб (железо/диски/SMART/события/`reboots`/`whea`/…) и заливает один структурированный
  `diag.md` в базу знаний. Один снапшот вместо россыпи ad-hoc ssh — экономия токенов.
- **Апдейтер клиента** — `SzDiag.Updater.exe` на клиенте находит hub, сверяет версию и сам
  тянет свежий пакет агента с хоста. Убирает ручной цикл раздачи через share: на клиента
  кладётся один раз `Updater.exe` + `appsettings.json`.
- **База знаний** (Obsidian-vault): по каждой СЗ пишется скелет, отчёты и итоговый
  `вывод.md` (блок «Для клиента» для колл-центра + техразбор); паттерны «симптом → причина»
  копятся отдельно.
- **Живая стресс-диагностика**: доставка стресс-тулов (OCCT/TM5/FurMark/3DMark) на клиента
  командой `szcli push` — агент сам качает файлы с hub по HTTP, sha256 сверяется, уже лежащее
  пропускается (SMB остался запасным вариантом для ручных случаев). Мониторинг сенсоров
  наблюдателем (CSV, переживает вырубон), разбор минидампов через `cdb`. Обкатано на кейсах
  спонтанных ребутов — воспроизведение дефекта под OCCT Power + дискриминация свопом
  компонента.
- **Резолвер видеокарт** по Windows PCI hardware ID: вендор/модель/чип из pci.ids +
  дорезолв точной партнёрской платы (SKU) и спеков прошивки из TechPowerUp VGA BIOS
  collection, кэш в SQLite. CLI: `szcli hw import/update/resolve`.

**Статус.** sshd под SYSTEM (план Б), RunDiag и апдейтер клиента — реализованы и
e2e-проверены на реальной онлайн-СЗ (2026-07-21): живой SSH-коннект, `diag run` даёт
полный `diag.md`, клиент самообновляется через `Updater.exe`. Прогон 2026-08-07 (СЗ 260306)
подтвердил на живой машине: наблюдатель нагрузки, `exec` под 100 % загрузкой, `push`/`pull`,
resume агента после ребута, watchdog, ручной откат ярлыком, `maintenance`. Что не сошлось —
пунктами в [docs/dev-backlog.md](docs/dev-backlog.md) (там же итоговая таблица прогона).

## Быстрый старт

```powershell
dotnet build           # сборка
dotnet test            # автотесты (~467, без хоста/клиента)
.\tools\doctor.ps1     # проверка бокса перед выездом
.\tools\build-dist.ps1 # готовый dist: dist\host\ (hub+cli) и dist\client\ (updater+agent)
```

Запуск: `dist\host\start-hub.cmd` (hub), `dist\host\szcli.cmd` (CLI), `SzDiag.Updater.exe`
на клиенте (сам подтянет агента). Подробный e2e-прогон и траблшутинг — в
[docs/TESTING.md](docs/TESTING.md).

## Структура

Восемь проектов в `src/` (+ зеркальные тесты в `tests/`): `SzDiag.Contracts` (DTO/протокол),
`SzDiag.Hub` (ASP.NET Core: SignalR для агентов + management API для CLI), `SzDiag.Cli`
(`szcli`), `SzDiag.Agent` (консоль на клиенте), `SzDiag.Updater` (самообновление клиента),
`SzDiag.ConsoleUi` (общий консольный UI: липкая панель статуса), `SzDiag.Hardware`
(резолвер видях), `SzDiag.Kb` (база знаний).
