# TM5 (TestMem5) для клиента — как не прогнать не тот профиль

TM5 — основной тест памяти на заявках «вимикається / BSOD під навантаженням». Главная
опасность у него не в самом тесте, а в том, что **профиль выбирается молча**: тест «идёт»,
только совсем не тот, что задумано, и в отчёте это никак не видно. На живой заявке это
означает ложное «память чистая».

## Откуда TM5 берёт профиль

По порядку, что реально решает:

1. **`TM5.ini`** рядом с `TM5.exe` — ключ `Config File=<имя>.cfg`. Это и есть выбор профиля;
   сами профили лежат в `bin\` (`Extreme @ anta777.cfg`, `Heavy @ anta777.cfg`,
   `Absolut @ anta777.cfg`, `DDR5 Ryzen3D @ anta777.cfg`, `1usmus v3 @ 1usmus.cfg` и пр.).
2. **`bin\Cfg.link`** — если он есть, TM5 читает конфиг по указанному в нём пути. На копии
   из шары там лежал **сетевой путь** (`\\mamoru\Share\Tests\TM5\MT.cfg`). На клиенте шара
   отмонтирована (так и надо по модели угроз), файл недоступен — и TM5 **тихо** сваливается
   на `bin\MT.cfg` с `Config Name=Default` (Tests=6, Time=100 %) вместо тяжёлого профиля.
   Ни ошибки, ни предупреждения (бэклог п.54).
3. `bin\MT.cfg` — дефолт последней надежды.

**Правило: `Cfg.link` на клиент не едет.** Профиль задаётся только через `TM5.ini`,
конфиги — локальные, в `bin\`.

## Проверка после запуска (обязательная)

TM5 показывает счётчик ошибок **только в GUI**, поэтому единственный машинно-читаемый
след — `Log.txt` рядом с `TM5.exe`:

```
-------- TestMem5 0.13.1 2026-08-06 14:02 --------
0:00:00  Configuration: Extreme @ anta777
0:00:00  Testing 1008 MB x 20 (61%) out of 32525 MB
```

Строка `Configuration:` — это и есть фактический профиль. Она обязана попадать в протокол
прогона: «гоняли TM5» без имени профиля — бесполезная запись.

```powershell
szcli exec <СЗ> "Select-String -Path 'C:\Client-test\tools\tm5\Log.txt' -Pattern 'Configuration:' | Select-Object -Last 1"
```

## Грабли запуска (проверено на живых СЗ)

- **Рабочая папка.** `schtasks /Create` её задавать не умеет — задача стартует с CWD
  `C:\Windows\System32`, и TM5 (32-битный → на самом деле `C:\Windows\SysWOW64`) кладёт
  `Log.txt` туда. Ставить задачу только через
  `Register-ScheduledTask -Action (New-ScheduledTaskAction … -WorkingDirectory <папка тула>)`.
- **Лог буферизуется.** Под SYSTEM без GUI `Log.txt` может 25 минут провисеть нулевым —
  подтвердить «прошло чисто» по нему нельзя, только отсутствие BSOD по `bootTime`.
- **Процесс умирает вместе с агентом**, если запущен из `szcli exec` напрямую: 35 минут
  прогона ушли в мусор, когда упал экземпляр агента (бэклог п.53). Запускать detached —
  scheduled task.
