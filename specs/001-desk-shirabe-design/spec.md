# Feature Specification: Редизайн Desk на дизайн-систему Shirabe

**Feature Branch**: `2027-desk-shirabe-design`
**Created**: 2026-10-19
**Status**: Draft
**Input**: Переделать визуальный дизайн SzDiag.Desk на дизайн-систему Shirabe («Оркестр»,
артефакт https://claude.ai/artifact/TYJjNu1apzCZjcvczfoPxy). Функционал не меняется — только вид.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Окно в языке Shirabe: рама, острова, тулбар, статус-бар (Priority: P1)

Оператор открывает Desk и видит окно в том же визуальном языке, что и Shirabe: тёмная рама,
на ней три острова со скруглением (слева — заявки, в центре — чат, справа — инспектор),
тулбар сверху с кнопками окна и статус-бар снизу. Всё, что раньше было в окне, на месте и
работает так же.

**Why this priority**: Это каркас — без него остальные экраны не во что вкладывать, и это
первое, что видит оператор.

**Independent Test**: Запустить Desk с живым hub и без него; сравнить окно с карточкой
MainWindow дизайн-системы: рама, острова, зазоры, высоты тулбара и статус-бара, кнопки окна.

**Acceptance Scenarios**:

1. **Given** Desk запущен, **When** окно открылось, **Then** видна рама цвета `bg.base`,
   три острова цвета `bg.surface-1` со скруглением 10 и зазором между ними, тулбар высотой 40
   и статус-бар высотой 24.
2. **Given** окно открыто, **When** оператор тянет пустое место тулбара, **Then** окно
   перемещается; двойной клик разворачивает/восстанавливает; кнопки «Свернуть / Развернуть /
   Закрыть» 46×40, у «Закрыть» при наведении — красная заливка с белой иконкой.
3. **Given** окно развёрнуто, **When** оператор смотрит на кнопку «Развернуть», **Then** её
   иконка сменилась на «Восстановить».
4. **Given** инспектор закрыт, **When** оператор открывает его кнопкой, **Then** справа
   появляется остров инспектора шириной 308, центр сужается; закрытие возвращает центр.

### User Story 2 - Список заявок и архив (Priority: P1)

Оператор видит в левом острове заявки: номер СЗ, подпись, строка железа, живость (точка +
слово в подсказке), бейджи `⚡N`, заморозки WU, похожей машины и переписки сессий, точку
состояния сессии. Внизу — секция «Без агента · архив». Выбор строки подсвечивается по правилам
дизайн-системы (с фокусом и без).

**Why this priority**: Основной инструмент навигации по работе дня.

**Independent Test**: Подать снапшот с несколькими СЗ разных состояний и архивными сессиями;
проверить вид строк, бейджей и выбора.

**Acceptance Scenarios**:

1. **Given** в работе 3 СЗ, **When** оператор смотрит на левый остров, **Then** заголовок
   секции «Заявки · 3» написан регистром предложения, строки высотой не меньше 26, цифры
   табличные.
2. **Given** у СЗ 2 вырубона и заморожен WU, **When** строка видна, **Then** бейджи «⚡2» и
   заморозки показаны монохромно/статусными цветами дизайн-системы, без эмодзи; смысл каждого
   бейджа доступен словом в подсказке.
3. **Given** строка выбрана и список в фокусе, **Then** фон — `bg.selected`; без фокуса —
   `bg.selected-inactive`.

### User Story 3 - Чат сессии Claude (Priority: P1)

В центральном острове над лентой закреплена шапка: номер СЗ · профиль Claude · состояние
сессии словом и точкой · кнопка «Открыть в терминале» · переключатель инспектора. Лента: реплики
оператора — на `bg.surface-2` (не акцентной заливкой), ответы Claude — текстом с разметкой, вызовы
инструментов — компонент ToolCall (моно-шрифт, сворачивание), запросы разрешений — ApprovalCard с
кнопками «Разрешить / Запретить», вопросы — QuestionCard. Поле ввода — компонент Composer,
очередь и кнопка остановки на месте.

**Why this priority**: Чат — центр работы оператора по заявке.

**Independent Test**: Открыть сессию с историей, содержащей все типы элементов ленты, и ход,
ждущий разрешения; сравнить с карточками ChatMessage, ToolCall, ApprovalCard, Composer.

**Acceptance Scenarios**:

1. **Given** сессия ждёт разрешения, **When** лента показывает запрос, **Then** карточка имеет
   рамку/акцент статуса `status.approval`, слово «Ждёт подтверждения» и основную кнопку акцентом.
2. **Given** вызов инструмента, **When** оператор кликает по заголовку, **Then** блок
   раскрывается/сворачивается; имя инструмента и аргументы — моно-шрифтом 12px.
3. **Given** ход идёт, **Then** точка состояния в шапке пульсирует — единственная анимация,
   кроме спиннера выполнения.

### User Story 4 - Инспектор СЗ (Priority: P2)

Правый остров: вкладки Обзор / Вырубоны / Задачи / Сенсоры / Журнал / Железо / Действия в виде
EditorTabs (высота 36, подчёркивание активной акцентом), содержимое — на токенах: подписи
`text.secondary`, значения `text.primary`, числа моно/табличные, кнопки действий — Button
(основная/вторичная/опасная).

**Why this priority**: Важен, но вторичен к списку и чату.

**Independent Test**: Пройти по всем вкладкам у СЗ с данными и без данных.

**Acceptance Scenarios**:

1. **Given** вкладка без данных, **When** она открыта, **Then** показано пустое состояние по
   компоненту EmptyStates (иконка + одна строка + при необходимости действие).
2. **Given** вкладка «Действия», **Then** разрушительные действия (close, revert) оформлены
   как опасные и отличаются не только цветом, но и подписью.

---

### User Story 5 - Нижняя панель передач, статус-бар, пустые состояния (Priority: P2)

Передачи `push`/`pull` показываются в нижней tool window центра (заголовок, ProgressBar на
каждую передачу), видимой только когда передачи есть. Статус-бар — компонент StatusBar: hub,
пакет агента, бэкап kb, туннель, токены за день — словами, `small` 12px. Пустой центр («Выбери
СЗ слева», сессия без агента, «Начать сессию») — по компоненту EmptyStates с полями Input и
кнопками Button.

**Why this priority**: Вспомогательные поверхности, но видны постоянно.

**Independent Test**: Запустить pull, выключить hub, открыть окно без выбранной СЗ.

**Acceptance Scenarios**:

1. **Given** hub недоступен, **Then** статус-бар пишет это словом со статусом `status.error`,
   а старые данные помечены «данные на ЧЧ:ММ».
2. **Given** в поле номера СЗ без агента введено «16200», **Then** поле в состоянии ошибки
   (рамка `status.error`) и под ним текст причины.

### Edge Cases

- Окно минимального размера (900×520): острова не наезжают друг на друга; при нехватке ширины
  инспектор закрывается, а не сжимает чат ниже читаемого.
- Длинные строки (подпись СЗ, железо, путь в ToolCall) обрезаются многоточием, полное значение —
  в подсказке.
- Шрифты Inter / JetBrains Mono отсутствуют в системе — окно всё равно рисуется ими (поставляются
  вместе с приложением), без подмены на системные.
- Масштаб Windows 125–150%: размеры остаются на сетке 4px, без размытых однопиксельных линий.
- Системный акцент Windows красный (как у оператора на 160176) — интерфейс его не подхватывает
  нигде.
- Много балунов/уведомлений — не появляются: нового механизма уведомлений фича не вводит.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Все цвета, отступы, радиусы, высоты и шрифтовые стили окна ДОЛЖНЫ браться из
  единого набора токенов, совпадающего по именам и значениям с `tokens.json` дизайн-системы
  (тёмная тема); захардкоженных цветов в экранах не остаётся.
- **FR-002**: Раскладка ДОЛЖНА следовать карточке MainWindow: тулбар 40 сверху, статус-бар 24
  снизу, острова на раме с зазором; колонки — заявки 268 · центр (резина) · инспектор 308.
- **FR-003**: Тулбар ДОЛЖЕН быть зоной перетаскивания окна с двойным кликом
  «развернуть/восстановить» и кнопками окна 46×40 по правилам дизайн-системы.
- **FR-004**: Интерфейс ДОЛЖЕН использовать шрифты Inter (интерфейс) и JetBrains Mono (код,
  вызовы инструментов, числа метрик) размеров 11–16 по шкале heading/title/body/body-medium/
  small/caption/code/code-small, цифры табличные.
- **FR-005**: Иконки ДОЛЖНЫ быть монохромными 16×16 с линией 1,2 и цветом текста; эмодзи в
  интерфейсе (`🧊`, `⚡`, `■`, `💬`) заменяются иконками набора.
- **FR-006**: Каждое состояние (живость СЗ, состояние сессии, статус передачи, hub) ДОЛЖНО
  передаваться словом или подсказкой со словом, а не только цветом; статусные цвета — только
  `status.*`.
- **FR-007**: Интерактивные элементы (кнопки, поля, вкладки, строки списков, переключатели)
  ДОЛЖНЫ иметь пять состояний дизайн-системы: default / hover / active / disabled / focus,
  с кольцом фокуса `border.focus`.
- **FR-008**: Акцент — один (`accent.*`); акцентной заливкой оформляются только основная кнопка,
  подчёркивание активной вкладки, прогресс и выбранный вариант. Реплики оператора в ленте —
  на `bg.surface-2`.
- **FR-009**: Тени ДОЛЖНЫ быть только у плавающих слоёв (меню, подсказки, диалоги); у островов
  теней нет.
- **FR-010**: Весь существующий функционал Desk ДОЛЖЕН остаться: те же данные, команды,
  горячие клавиши, привязки и поведение; существующие автотесты Desk проходят без правок
  логики.
- **FR-011**: Тексты интерфейса — по правилам тона дизайн-системы: регистр предложения
  («Заявки», «Без агента · архив» вместо капса), без восклицаний, десятичная запятая
  в числах, время «сейчас / 2 мин / 1 ч».
- **FR-012**: Брендовые цвета иконки Shirabe (розовый/красный «Сакура») в интерфейсе
  не используются; у Desk своя иконка в тех же правилах (монохромная, без чужих логотипов).

### Key Entities

- **Набор токенов**: семантические имена (`bg.*`, `border.*`, `text.*`, `accent.*`, `status.*`,
  `space.*`, `radius.*`, `size.*`, шрифтовые стили) → значения тёмной темы. Единственный источник
  вида для всех экранов.
- **Компонент дизайн-системы**: Button, Input, Select, Toggle, SegmentedControl, EditorTabs,
  StatusDot, LimitBadge, ToolCall, ApprovalCard, QuestionCard, Composer, ChatMessage,
  ProgressBar, StatusBar, EmptyStates, Tooltip — стиль, переиспользуемый всеми экранами.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% экранов Desk (список, архив, чат и все типы элементов ленты, 7 вкладок
  инспектора, передачи, статус-бар, 3 пустых состояния) переведены на токены; поиск
  захардкоженных цветов в разметке окна даёт 0 совпадений.
- **SC-002**: Оператор, видевший Shirabe, узнаёт в Desk тот же визуальный язык: при сравнении
  скриншота главного окна с карточкой MainWindow расхождений в цветах, высотах, радиусах и
  шрифтах нет (сверка по чек-листу токенов).
- **SC-003**: Ни одна функция Desk не потеряна: все существующие автотесты Desk зелёные,
  живой прогон по чек-листу Desk (сессия, разрешение, инспектор, push/pull, сессия без агента)
  проходит без отличий в поведении.
- **SC-004**: Контраст: вторичный текст и рамки полей держат не ниже 4,5:1 и 3:1 на всех
  поверхностях (как задано токенами).
- **SC-005**: В интерфейсе 0 эмодзи; каждое цветовое состояние имеет словесную расшифровку.

## Assumptions

- Только тёмная тема; светлая — позже второй темой с теми же именами токенов (вне scope).
- Источник истины — опубликованная версия артефакта Shirabe на 2026-10-19 (токены, README,
  карточки компонентов); сами файлы дизайн-системы в репозиторий не копируются, кроме
  перенесённых значений токенов и шрифтов.
- Шрифты Inter и JetBrains Mono (лицензия OFL) поставляются внутри приложения — бокс может
  быть без интернета и без этих шрифтов в системе.
- Новых возможностей не добавляется: «Активность» с субагентами, стопка уведомлений, полосы
  tool windows, диалоги настроек и мастер первого запуска Shirabe в Desk не переносятся —
  у Desk для них нет функционала. Полосы tool windows не вводятся; инспектор открывается
  существующим переключателем в шапке чата.
- Нижняя tool window центра — существующая панель передач в оформлении дизайн-системы;
  ручка изменения её высоты не вводится.
- Расход контекста сессии в шапке чата показывается, только если Desk уже знает эти данные
  (токены сессии); новых источников данных фича не вводит.
