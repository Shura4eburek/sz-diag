Инфраструктура со своим контроллером ZeroTier

Фича 002 · domain-independent-access · вариант «без ZeroTier Central» · черновик 2026-11-24. Конкретные адреса и имена проекта Railway сюда намеренно не вписаны: каждый поднимает свой.

Схема

HTTPS через публичный адрес Railway · ZeroTier сплошная — трафик данных, пунктир — служебный (конфиг сети, корни)

Поток заявки

  1. Hub стартует, берёт аренду в указателе и публикует подписанную запись: адрес hub в сервисной сети, ID сети, версия агента.
  2. Апдейтер на клиенте не нашёл hub в LAN → читает указатель, проверяет подпись ключом флота, вшитым в exe. Адрес Railway доверия не даёт, доверие даёт подпись.
  3. Агент поднимает libzt и входит в сеть по ID. Сеть публичная, поэтому член получает адрес из пула 10.88.0.0/24 сразу, без ручного authorize.
  4. SignalR, /tools, /agent и проброс SSH идут P2P по ZeroTier к hub. Защиту по-прежнему держат токен агента и секрет сессии, как сейчас.
  5. Закрытие СЗ: агент выходит из сети и стирает storage, hub удаляет член через прокси контроллера. Сторож на hub раз в минуту удаляет члены без активной СЗ старше 10 минут: это добирает headless-откаты и посторонних.

Flow rules сервисной сети (черновик)

# только IPv4 и ARP
drop not ethertype ipv4 and not ethertype arp;
accept ethertype arp;

# клиент разговаривает только с hub-машинами (ПК .1, ноут .2), клиент↔клиент — нет
accept ipdest 10.88.0.1/32;  accept ipsrc 10.88.0.1/32;
accept ipdest 10.88.0.2/32;  accept ipsrc 10.88.0.2/32;
drop;

Сузить до порта hub и 22 можно правилами dport. Это решится в T037, синтаксис проверить компилятором правил контроллера.

Риски и что проверить первым

Railway и исходящий UDP. Контроллеру нужен исходящий UDP до корней ZeroTier. Входящий не нужен: работают NAT и relay. Это не проверено. Первый шаг — деплой пустого zerotier-one и проверка, что zerotier-cli info показывает ONLINE. Не проходит — контроллер переезжает на любой маленький VPS, схема та же.
Потеря identity контроллера = потеря сети. ID сети начинается с адреса контроллера. Volume пропал → новый ID → клиенты со старым указателем не войдут. Лечится бэкапом identity.secret в зашифрованный бандл флота при fleet.ps1 init.
Контроллер лежит. Уже вошедшие члены держат конфиг некоторое время, новые СЗ не войдут. Канал остаётся: LAN-discovery и quick tunnel работают без ZT.
Лицензия. libzt 1.8.4 с 2026-01-01 под Apache 2.0. Контроллер в zerotier-one идёт под своей лицензией (BSL/коммерческой). Самохостинг для себя, не как платный сервис, — посмотреть по их текущему тексту лицензии перед деплоем.

Порядок развёртывания

  1. Railway: сервис zt-controller с volume. Проверить ONLINE (риск UDP).
  2. Создать сервисную сеть, пул 10.88.0.0/24, flow rules. ID сети — в бандл флота.
  3. ПК и ноут: zerotier-cli join <сеть> (один раз, под админом), статические .1/.2 через API, личная сеть — в Hub.DenySubnets.
  4. Спайк T035, пункты 2–4: два libzt-процесса в этой сети.
  5. Дальше — T038–T050 по плану.
