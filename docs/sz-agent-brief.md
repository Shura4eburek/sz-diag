# Субагент на заявку: бриф и журнал смены

Как ведём живые СЗ: **на каждую заявку — свой именованный субагент**, чтобы параллельные
заявки не мешались в одной голове, а контекст по каждой копился отдельно.

## Что переживает сессию, а что нет

Проверено 2026-08-04 (не по памяти, а по диску):

| Что | Живёт | Комментарий |
|---|---|---|
| Транскрипт субагента | до конца сессии | `SendMessage` по имени возобновляет агента **с контекстом**, но только в той же сессии |
| Штатный task-лист | до конца сессии | лежит в `~/.claude/tasks/<id-сессии>/<n>.json` — каталог на сессию; в прошлых сессиях остались только `.lock`/`.highwatermark`, задач нет |
| kb-карточка СЗ | всегда | `kb/СЗ/<номер>/` — `діагностика.md`, `дії.md`, `висновок.md` |
| Журнал смены | всегда | `kb/Журнал/<YYYY-MM-DD>.md` (см. ниже) |

Вывод: **всё, что нужно завтра, должно осесть в kb** — агент сам по себе не переживает
ночь. Новый агент с тем же именем — это не «тот же самый», он читает kb и въезжает заново.

## Правила ведения

1. Заявка пришла → поднять агента с именем `sz-<номер>` (модель — наследовать модель
   сессии: диагностика это не рутина) и завести задачу в task-листе, чтобы «что сейчас
   делается» отвечалось по списку, а не по памяти.
2. Агент по ходу пишет факты в `діагностика.md` / `дії.md` — цифры, коды ошибок, что
   свопнули, что исключили. Не «в голове».
3. Каждый значимый шаг → строка в журнал смены.
4. Наткнулся на костыль/потерю времени → пункт в `docs/dev-backlog.md` в тот же заход
   (правило «споткнулся — запиши» из CLAUDE.md).

## Журнал смены

Файл: `kb/Журнал/<YYYY-MM-DD>.md` (kb в `.gitignore` — данные клиентов в гит не уезжают).

```markdown
# 2026-08-04

- **161288** | agent `sz-161288` | OCCT 40 хв, помилки на JEDEC 4800 → не EXPO
  → далі: свопнути плашки, повторити тест
- **160176** | agent `sz-160176` | чекаємо ребут під навантаженням
  → далі: зняти whea після ребуту
```

Формат строки: `номер СЗ | имя агента | что сделано (факты) | → далі: следующий шаг`.
Именно «→ далі» я читаю первым делом на следующий день.

## Шаблон брифа субагенту

Субагент **видит** `CLAUDE.md` проекта, репо и kb. Субагент **не видит** личную память
Claude — всё оттуда кидать в бриф явно. Ниже постоянная часть + дырки под заявку.

```
Ты ведёшь СЗ <НОМЕР>. Работай до результата, факты пиши в kb по ходу, не в конце.

Заявка:
- симптом со слов клиента: <...>
- железо: <CPU / плата / память / БЖ / видяха>
- что уже пробовали: <...>
- гипотезы: <...>

Контекст проекта: читай CLAUDE.md. Плюс грабли, которых нет в репо:

- SMB-доставка тулов на клиента: шара \\<hub-ip>\Share (хост C:\Share),
  стресс-тулы в Tests\client\client-tools\ (tm5/occt/furmark/3dmark).
  Гостевой SMB на Win10/11 закрыт → монтировать ТОЛЬКО с явными кредами
  (логин/пароль спроси у меня, в гите их нет): net use \\<hub-ip>\Share <pass> /user:<usr>
- szcli exec — всегда через -f <файл>, никогда inline-строкой: хостовый PowerShell
  жрёт $-переменные. В шапку скрипта — UTF8.
- В скриптах НЕ собирать элементы массива конкатенацией: в PowerShell запятая
  связывает сильнее «+», и @('a', 'b' + $x + 'c') превращается в четыре элемента
  вместо двух (на 161312 так развалился генерируемый .bat, сорок минут искали не
  там). Писать ('b' + $x + 'c') в скобках либо here-string @"..."@.
- Тулзы кладём только в tools\<tool>\ рядом с agent.exe. Никаких C:\szdiag-tools.
- PowerShell по SSH — через -EncodedCommand (base64 UTF-16LE): обходит кавычки,
  кириллицу, локаль и CLIXML.
- Под нагрузкой sshd глохнет → долгие вещи запускать detached через scheduled task
  под SYSTEM, а не Start-Process из SSH-сессии.
- Паттерн ≠ вердикт: знакомую связку всё равно проверяй на стоковых настройках
  (на 161288 «очевидный EXPO» оказался не EXPO — ошибки лезли на JEDEC 4800).
- Споткнулся о костыль или потерял время — пиши пункт в docs/dev-backlog.md с фактами.

По ходу работы:
- факты → kb/СЗ/<НОМЕР>/діагностика.md, действия → дії.md (украинский)
- строка в kb/Журнал/<сегодня>.md после каждого значимого шага
- вопросы ко мне — через отчёт, напрямую к юзеру ты не ходишь
```

Креды SMB в этот файл **не вписываем** — они живут в личной памяти и передаются в бриф
на месте.
