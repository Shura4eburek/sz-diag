# Живая проверка: доступ через Cloudflare Tunnel (2026-09-14)

Проверяется на первой же онлайн-СЗ. До прохождения этого списка схема остаётся
**дополнением** к прямому доступу, а не заменой: прямой SSH в локальной сети не выключен,
`AccessMode = Direct` — это он и есть.

Спека — [2026-09-14-cloudflare-tunnel-access-design.md](superpowers/specs/2026-09-14-cloudflare-tunnel-access-design.md),
план — [2026-09-14-cloudflare-tunnel-access.md](superpowers/plans/2026-09-14-cloudflare-tunnel-access.md).

## Подготовка на боксе

- [ ] `cloudflared` установлен на боксе (`build-dist` кладёт его в каталог раздачи сам)
- [ ] Именованный туннель на хаб поднят, `hub.<домен>` отвечает снаружи
- [ ] Access-приложение и service token заведены
- [ ] `build-dist.ps1 -HubUrl https://hub.<домен> -AccessClientId … -AccessClientSecret …`
- [ ] `szcli push --list` показывает `cloudflared`

## Базовый поток

- [ ] Агент подключился к hub **по домену** (не broadcast'ом) — `szcli list` показывает online
- [ ] `szcli push <СЗ> cloudflared` доставил бинарь, sha256 сошёлся
- [ ] Агент поднял туннель; в `szcli list` у СЗ виден режим `tunnel`
- [ ] `szcli target <СЗ>` печатает строку с `ProxyCommand`
- [ ] Строка скопирована и вставлена **как есть** — SSH подключился
- [ ] В строке `StrictHostKeyChecking=yes`, подключение прошло без предупреждений о ключе

## Скорость и задержка

Замер на боксе (17 MB/s) **не показателен**: оба конца были на одном канале, трафик ушёл
и вернулся через один аплинк. Здесь снимается реальная цифра.

- [ ] `szcli pull` файла 50+ МБ: ____ MB/s
- [ ] Задержка интерактивного SSH: печать не отстаёт / отстаёт
- [ ] Сравнить с прямым режимом на той же машине, если она в LAN бокса: ____ MB/s

## Ребут

- [ ] После ребута клиента СЗ вернулась online сама
- [ ] `AccessHost` **другой**, чем был до ребута (quick tunnel не сохраняет hostname)
- [ ] `szcli target` ведёт на новое имя, подключение работает
- [ ] `known_hosts` этой СЗ перезаписан под новое имя, ssh не ругается на смену ключа

## Под нагрузкой

- [ ] Под OCCT туннель жив (сейчас под нагрузкой глохнет sshd — проверить, глохнет ли туннель)
- [ ] `szcli exec --detach` по-прежнему проходит
- [ ] Если туннель отвалился: сессия осталась online, `target` честно сказал о недоступности

## Честность и откат

- [ ] При снятом туннеле `szcli target` говорит «туннель не поднят», а не печатает строку
- [ ] `szcli close` откатил всё: задачи `szdiag-cfd-*` нет, процесса `cloudflared` нет
- [ ] `szcli client info` не показывает остатков
- [ ] Откат туннеля прошёл **раньше** снятия sshd (видно по `revert.log`)

## Секрет сессии

- [ ] Watchdog-откат (или `--revert` вручную) отчитался hub успешно — значит заголовок
      `X-SzDiag-Session` доехал и сверка прошла
- [ ] В `state.json` на клиенте есть `SessionSecret`
