## Основной список

### 159873 — дефектный экземпляр IMC 7500F

- **Конфигурация:** ASUS PRIME B650M-K (BIOS 3263) / Ryzen 5 7500F / RTX 5060 /
  **Crucial DDR5 Pro OC 6000 `CP16G60C36U5B` 1×16** (JEDEC 5600, Configured **6000** = EXPO),
  БЖ Gigabyte P650SS.
- **Дефект:** мгновенный hard-off без BSOD и без WHEA под нагрузкой. OCCT Power валит машину
  (~10 мин), 5 ч RDR2 — не валят.
- **Разбор:** своп БЖ не помог; 6000→5600 продлило (10→18 мин), но не вылечило; тестовая память
  5600 dual — падение за 20-40 с → память исключена. Своп 7500F→8700F держит.
- **Вердикт:** дефектный экземпляр процессора (IMC), не политика EXPO. Процессор заменён,
  верифицировано 27.07 (новый 7500F: OCCT Power 42 мин на 5600 single, 0 KP41/WHEA/dump).
- **Статус:** отремонтировано.

### 160176 — нестабильность памяти под EXPO 6000

- **Конфигурация:** MSI B850 GAMING PLUS WIFI6E (BIOS 1.A53) / Ryzen 5 7500F / RTX 5060 /
  **Kingston Fury `KF560C36-16` 2×16 DDR5-6000 CL36**, Configured **6000** (EXPO).
- **Дефект:** 35 внезапных перезагрузок/выключений за месяц — под нагрузкой и в простое.
  ~32 из 35 Kernel-Power 41 с `BugcheckCode=0` (жёсткий обрыв), 2 BSOD разными кодами
  (`0x50` через `WdFilter.sys` и `0xA0`), WHEA пусто.
- **Разбор:** разброс кодов исключает драйвер; `WdFilter` в дампе — «невинный свидетель» битой
  памяти. Классический почерк нестабильной RAM/EXPO на AM5.
- **Вердикт (предварительный):** нестабильность памяти (EXPO 6000 + IMC 7500F), вторая версия —
  питание. Ждал контрольного прогона с EXPO off.
- **Статус:** диагностировано. **Это опорный кейс системной связки 7500F + DDR5-6000.**

### 160450 — два дефектных узла: процессор (IMC) И память

- **Конфигурация:** MSI B850M GAMING PLUS WIFI6E / Ryzen 5 7500F / RTX 5070 /
  **Kingston Fury Beast `KF560C36-16` (кит `KF560C36BBE2K2-32`) 2×16 DDR5-6000 CL36**,
  Configured **6000** (EXPO), dual-channel.
- **Дефект:** россыпь memory-BSOD: `0x1A`, `0x4E` PFN_LIST_CORRUPT, `0x50`, `0xBE` (×6),
  `0x13A` heap corruption. WHEA пусто (non-ECC). Дамп `0xBE`: `AV_nt!MiRaisedIrqlFault` —
  битая PTE, один и тот же `param2` 15.07 и 23.07 → устойчивая битовая ошибка.
- **Разбор:** перекрёстный своп — клиентский проц + тестовая память = сбои; тестовый проц +
  клиентская память = сбои; тестовый проц + тестовая память = норма. JEDEC не спасал.
- **Вердикт:** неисправны **оба** узла — процессор (IMC) и память, замена по гарантии;
  Windows добита corruption → переустановка.
- **Статус:** отремонтировано.

### 161288 — память бьётся даже на заводском стоке (EXPO ни при чём)

- **Конфигурация:** ASUS PRIME B650M-K (BIOS 3842 → прошит 3886) / Ryzen 5 7500F /
  **GoodRAM `IRK-HX60D564L36S/16G` 2×16 DDR5-6000**, на приёмке Configured **6000** (EXPO вкл).
  Сборка HEXO Gaming.
- **Дефект:** 137 Kernel-Power 41 + 86 BugCheck 1001 с 11.06.2025. Минидампы — `0x7E` (`Ntfs.sys`
  ×2), `0xBE` ATTEMPTED_WRITE_TO_READONLY_MEMORY (`ntkrnlmp`), `0x50` (`CI.dll`). Модули каждый
  раз разные → почерк битой памяти. WHEA пусто.
- **Разбор:** EXPO выключен → JEDEC 4800: TM5 `Heavy5opt` дал **10 ошибок за 1 ч 01 мин** на
  стоке, следом BSOD `0x154` через `MemCompression`. Версия «снизить 6000→5600» опровергнута —
  дефект живёт на заводском стоке. Проверка сервисным комплектом сорвалась: вторая планка
  сервисного кита оказалась мёртвой (отсюда ложный «1 длинный + 2 коротких» = память не найдена);
  подозрение на плату/сокет/IMC снято, родной GoodRAM в двухканале стартует.
- **Развязка (18.08):** поставили **другой комплект памяти** — на **EXPO 5600 всё работает
  нормально, сбоев нет**. На родном GoodRAM ошибки лезли даже на JEDEC 4800 → подозрение на
  комплект GoodRAM. Следом в сборке заменили **и процессор** (новый пришёл отдельно).
- **Вердикт:** предварительный — дефектный комплект памяти GoodRAM. Прогона после замены
  процессора ещё не было, приборно новая пара не подтверждена.
- **Статус:** в работе, ждёт контрольный прогон (TM5 Heavy5opt от админа ~1 ч на 5600 + контроль
  на JEDEC 4800). ⚠️ Память и проц заменены разом — дискриминация утеряна; разделяет только
  промежуточный шаг «новая память + старый проц на 5600 — чисто».

### 161716 — паттерн по конфигурации, но приборно не подтверждён

- **Конфигурация:** Gigabyte B850M EAGLE WIFI6E (BIOS F10b от 30.06.2026) / Ryzen 5 7500F /
  RTX 5070 / **Kingston FURY `KF560C30-8` 2×8 DDR5-6000 CL30** single-rank, Configured **6000**.
- **Дефект:** 5 hard-off (`Bugcheck=0`, `PowerButtonTs=0`), все за 52 минуты 20.07.2026,
  первый — через 3.3 ч после установки ОС. BSOD 0, минидампов 0, WHEA 0.
- **Разбор:** повторное обращение (после 159530, где списали на старую прошивку) — прошивка
  свежайшая, версия опровергнута. Игровые сессии закрылись штатно, все выключения **на простое**.
  y-cruncher VT3+N63+FFTv4 75 мин и `stress-transient` 90 мин — чисто. OCCT не гнали (лицензия
  просрочена ровно 13.08).
- **Вердикт:** не воспроизведено. Прогон 6000 vs 5600/JEDEC (разница и есть вердикт) не доведён —
  заказчик остановил работы.
- **Статус:** в работе, СЗ не закрыта. ⚠️ перед выдачей `szcli unfreeze 161716`.

## Пограничные (память проверена и исключена)

### 160467 — дефектный процессор, память на JEDEC

- **Конфигурация:** MSI B850M GAMING PLUS WIFI6E (BIOS 1.A42) / Ryzen 5 7500F (tray) /
  MSI RTX 5060 Ti 16GB / **Kingston `KF560C36BBE2K2-32` 2×16 DDR5-6000 CL36**, но
  **EXPO выключен — работала на 4800 JEDEC**.
- **Дефект/вердикт:** 7 WHEA Corrected Machine Check `Cache Hierarchy Error` от Processor Core
  на стоковой памяти + 40+ KP41 `BugcheckCode=0`. Своп 7500F→8700F: 33 мин CS2 чисто (до свопа —
  вырубон за ~5 мин). Дефектный процессор; EXPO/память как причина исключены профилем 4800.

### 160587 — заводской дефект CPU, память на стоке

- **Конфигурация:** ASUS PRIME B650M-K / Ryzen 5 7500F / RTX 5060, память `Speed` =
  `ConfiguredClockSpeed` = **4800 JEDEC** (EXPO выключен).
- **Дефект/вердикт:** 276 корректируемых MCE на одном ядре с 24.02.2026 → заводской дефект CPU,
  процессор заменён 13.08.2026. Паттерн 7500F+DDR5-6000 исключён приборно. Причина hard-off
  (все четыре — на простое) не локализована; после замены профиль подняли 4800→5600, и
  **на 5600 память не проверена**.

## Примечания

- **160182** — тоже 7500F (Gigabyte / RTX 5070 / 32GB DDR5), но дефект — неисправный БЖ,
  подтверждён свопом. К памяти отношения не имеет.
- **159794** — 7500F (MSI B650 / RTX 4070 Super), вне гарантии: залитие/коррозия.
- Не-7500F кейсы того же паттерна DDR5-6000 EXPO: **161432** (9800X3D + Kingston FURY Beast
  2×32 DDR5-6000, ошибки CPU+RAM на XMP при чистом JEDEC, воспроизведено на двух идентичных
  сборках), **160697** (7800X3D + FURY 2×16 6000, hard-off без WHEA, версия не закрыта).
- Обоснование политики (почему заводской EXPO 6000 на Zen4 без «X» — плохая идея, механизм
  частотный, а не «напряжения»): kb-заметка
  «Чому DDR5-6000 EXPO на Ryzen 7500F — погана заводська політика» и
  [ddr5-6000-vs-5600-7500f-rationale.md](ddr5-6000-vs-5600-7500f-rationale.md).
- **Дискриминатор политика vs брак экземпляра:** 6000→5600 убрало вырубоны → политика EXPO;
  падает и на 5600 (ненормально рано) → своп процессора (дефектный IMC).
