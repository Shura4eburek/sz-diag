# Додаток до обґрунтування: перелік заявок (7500F + пам'ять)

Супровід до [ddr5-6000-vs-5600-7500f-rationale.md](ddr5-6000-vs-5600-7500f-rationale.md) —
там кейси знеособлені (A, B, C, D), тут ті самі машини **з номерами СЗ**, щоб відділ збірки міг
підняти будь-яку заявку й перевірити дані самостійно.

Дані зняті агентом віддаленої діагностики (липень–серпень 2026): `System.evtx`, мінідампи,
профіль пам'яті по SMBIOS (`Speed` = база SPD, `ConfiguredClockSpeed` = фактична частота),
прогони OCCT / TM5 / y-cruncher.

## 1. Заявки з питанням по пам'яті / IMC

### 159873 — дефектний екземпляр процесора (кейс B)

| | |
|---|---|
| **Конфігурація** | ASUS PRIME B650M-K (BIOS 3263) / Ryzen 5 7500F / RTX 5060 / Crucial `CP16G60C36U5B` **1×16 DDR5-6000**, БЖ Gigabyte P650SS |
| **Профіль на приймання** | `Speed` 5600 → `ConfiguredClockSpeed` **6000** (EXPO увімкнено) |
| **Дефект** | Миттєвий hard-off без BSOD і без WHEA під навантаженням. OCCT Power валив за ~10 хв, 5 год RDR2 — не валили |
| **Дискримінація** | Своп БЖ — не допоміг; 6000→5600 подовжило (10→18 хв), але не вилікувало; тестова пам'ять падала теж; своп 7500F→8700F — тримає |
| **Вердикт** | **Бракований екземпляр процесора (IMC)**, не політика 6000. Процесор замінено, верифіковано 27.07: новий 7500F на 5600 single — OCCT Power 42 хв, 0 KP41/WHEA/дампів |
| **Статус** | Відремонтовано |

### 160176 — нестабільність пам'яті під EXPO 6000 (кейс A)

| | |
|---|---|
| **Конфігурація** | MSI B850 GAMING PLUS WIFI6E (BIOS 1.A53) / Ryzen 5 7500F / RTX 5060 / Kingston Fury `KF560C36-16` **2×16 DDR5-6000 CL36** |
| **Профіль на приймання** | `ConfiguredClockSpeed` **6000** (EXPO із заводу, клієнт не чіпав) |
| **Дефект** | 35 Kernel-Power 41 за 30 днів, ~32 з них `BugcheckCode=0` (жорсткий обрив); WHEA порожній на всіх рівнях; лише 2 BSOD і **різними кодами** (`0x50`, `0xA0`) |
| **Розбір** | Дамп `0x50`: `WdFilter.sys` (Defender) без стороннього драйвера в стеку → «невинний свідок» битої пам'яті. Розбіжність кодів виключає драйвер |
| **Вердикт** | **Нестабільність пам'яті під EXPO 6000 + IMC 7500F** (друга версія — живлення). Чекав контрольного прогону з EXPO off |
| **Статус** | Діагностовано |

### 160450 — два дефектних вузли: процесор і пам'ять

| | |
|---|---|
| **Конфігурація** | MSI B850M GAMING PLUS WIFI6E / Ryzen 5 7500F / RTX 5070 / Kingston Fury Beast `KF560C36-16` (кит `KF560C36BBE2K2-32`) **2×16 DDR5-6000 CL36**, dual-channel |
| **Профіль на приймання** | `ConfiguredClockSpeed` **6000** (EXPO) |
| **Дефект** | Розсип memory-BSOD: `0x1A`, `0x4E` PFN_LIST_CORRUPT, `0x50`, `0xBE` (×6), `0x13A`. WHEA порожній (non-ECC). Дамп `0xBE` — `AV_nt!MiRaisedIrqlFault`, той самий `param2` 15.07 і 23.07 = стійка бітова помилка |
| **Дискримінація** | Перехресний своп: клієнтський проц + тестова пам'ять — збої; тестовий проц + клієнтська пам'ять — збої; тестовий проц + тестова пам'ять — норма. JEDEC не рятував |
| **Вердикт** | **Несправні обидва вузли — процесор (IMC) і пам'ять**, заміна за гарантією. Windows добита corruption → перевстановлення |
| **Статус** | Відремонтовано |

### 161288 — дефект живе на заводському стоці (кейс D, контрприклад)

| | |
|---|---|
| **Конфігурація** | ASUS PRIME B650M-K (BIOS 3842 → прошито 3886) / Ryzen 5 7500F / GoodRAM `IRK-HX60D564L36S/16G` **2×16 DDR5-6000**. Збірка HEXO Gaming |
| **Профіль на приймання** | `ConfiguredClockSpeed` **6000** (EXPO) |
| **Дефект** | 137 Kernel-Power 41 + 86 BugCheck 1001 з 11.06.2025. Дампи `0x7E` (`Ntfs.sys` ×2), `0xBE` (`ntkrnlmp`), `0x50` (`CI.dll`) — «винуватці» щоразу різні. WHEA порожній |
| **Ключова перевірка** | EXPO вимкнено → **JEDEC 4800**: TM5 `Heavy5opt` — **10 помилок за 1:01**, слідом BSOD `0x154` у `MemCompression`. Тобто дефект **не залежить від профілю** |
| **Розв'язка (18.08)** | Поставлено **інший комплект пам'яті** — на **EXPO 5600 машина працює нормально, збоїв немає** → підозра на комплект GoodRAM. Слідом у збірці замінено **ще й процесор** |
| **Вердикт** | Попередній: дефектний комплект пам'яті. ⚠️ Пам'ять і процесор замінені **разом** — прогону після заміни ще не було, тож остаточної дискримінації немає |
| **Статус** | В роботі, чекає контрольний прогін (TM5 `Heavy5opt` ~1 год на 5600 + контроль на JEDEC 4800) |

> **Для збірки головне з цього кейсу:** зниження профілю — обов'язковий перший крок, але **не
> заміна перевірці**. Без контрольного прогону машина поїхала б до клієнта на 5600 і повернулась
> би вчетверте.

| | |
|---|---|

## 4. Що з цього переліку доводить пропозицію, а що ні

**Доводить (за це варто триматися в розмові):**

- **160176** — розгін із нашої збірки, класичний підпис битої пам'яті, клієнт нічого не чіпав.
- **161432** — **дві ідентичні машини** дали однаковий результат на JEDEC і на 6000. Найсильніший
  доказ, бо два незалежні екземпляри виключають «брак модуля» і «брак процесора».
- **159873** — зниження до 5600 як **безкоштовний діагностичний фільтр**: політика лікується
  зниженням, брак екземпляра — ні, і це видно за один захід.

**Не доводить (і про це треба сказати самим, щоб не спіймали):**

- **161288** — дефект відтворюється **на заводському стоці**, профіль ні до чого.
- **160467**, **160587** — WHEA / MCE на **стоковій пам'яті 4800**, тобто браковані процесори:
  розгін там ні до чого взагалі.
- **161716** — конфігурація патерну, але дефект **не відтворився** ні рівним, ні транзієнтним
  навантаженням; усі вимкнення були на простої.

**Чесне формулювання для наради:** зниження профілю до 5600 **не прибирає гарантійні заявки як
клас** — браковані процесори, БЖ і дефектна пам'ять нікуди не дінуться. Воно прибирає **одну
конкретну версію з дошки на самому початку діагностики** (і в частині машин — сам дефект),
причому безкоштовно: ціна питання — одиниці відсотків FPS, підстава — офіційна специфікація
AMD для 7500F (**DDR5-5200** для двох модулів), тобто 6000 у нас іде поза паспортом.

## Примітка про повноту

У базі знань сервісу зараз **9 заявок** на збірках з Ryzen 5 7500F із заповненою карткою
(перелічені вище). Цифри в розділі «Що каже наш потік загалом» самого обґрунтування взяті з
ширшого зрізу (усі заявки віддаленої діагностики за липень–серпень 2026, разом із тими, де
картка ще не заповнена) — перед подачею цифри варто звірити, щоб на нараді не розійтися
з переліком.
