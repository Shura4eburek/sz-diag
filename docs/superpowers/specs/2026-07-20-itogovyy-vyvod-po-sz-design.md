# Итоговый вывод по СЗ + база паттернов симптомов

Дата: 2026-07-20

## Цель

Сейчас данные в KB текут двумя несвязанными потоками: сырой `report.md` (дамп прогона
testsuite, без интерпретации) и структурированные знания (`findings/actions` + frontmatter,
пишутся руками через `szcli kb`). Для двух задач этого мало:

1. **Отдать клиенту через колл-центр** — нужен готовый нетехнический текст «что с
   устройством, что сделали, итог».
2. **Обучение диагностике** — нужна воспроизводимая связка `симптом → показания →
   рассуждение → диагноз → что помогло`, чтобы Claude учился ставить диагнозы, а не
   перечитывал сырые прогоны.

Плюс жёсткое требование: **минимум токенов на поиск**. При новой СЗ Claude должен найти
релевантный паттерн одним точечным поиском, а не читать все СЗ подряд.

Красота сырого `report.md` из scope **исключена** осознанно — его не трогаем.

## Что делаем

Два новых типа заметок в Obsidian-vault и код-слой для генерации их скелета:

- **`kb/СЗ/<sz>/вывод.md`** — итоговый вывод по конкретной СЗ. Два блока: клиентский
  (копипаст в колл-центр) и технический разбор (для сервиса и обучения).
- **`kb/Симптомы/<симптом>.md`** — накопительный паттерн диагностики, ключуемый
  симптомом. Копит наблюдавшиеся причины по всем СЗ в одной точке.

Разделение труда — **гибрид**: код генерит скелет с плейсхолдерами и мёржит frontmatter
(идемпотентность, Dataview-линки), содержательную прозу (клиентский текст, рассуждение,
диагноз, причины) вписывает Claude напрямую через Edit/Write.

## Ключевое архитектурное решение: единый frontmatter

Frontmatter, который индексирует Dataview, живёт **только в `<sz>.md`** (home note).
`вывод.md` — прозовая заметка **без собственного YAML**, встраивается в home note через
`![[вывод]]`. Иначе Dataview увидел бы два файла с `сз:` в одной папке и задвоил бы СЗ во
всех таблицах.

Home note `<sz>.md` расширяется тремя новыми ключами:

- `симптом: []` — список линков `"[[<симптом>]]"`; по нему заметка симптома через
  Dataview собирает все свои СЗ.
- `статус: ""` — `диагностика | ждёт запчасть | готово | отказ`.
- `вердикт: ""` — `подтверждён | не подтверждён | иное` (подтвердился ли заявленный дефект).

## Структура `вывод.md`

Прозовый файл, без frontmatter. Скелет генерится с плейсхолдерами, Claude заполняет.

```markdown
# Вывод по СЗ <sz>

## 📞 Для клиента
> Простым языком, без терминов. Копируется в колл-центр как есть.

**Что с устройством:** …
**Что сделали:** …
**Итог / рекомендации:** …

---

## 🔧 Технический разбор
*для сервиса и обучения — клиенту не отдаётся*

**Симптом (со слов клиента):** …

**Показания диагностики:**
- … (цифры: температуры, SMART, коды ошибок)
- 🔗 сырой прогон: [[reports/<timestamp>/report.md]]
- ![[reports/<timestamp>/screen-N.png]]

**Рассуждение:** как из показаний вывелся диагноз (главное для обучения).

**Диагноз:** …

**Что помогло:** … + контрольные цифры после ремонта.

**Паттерн:** [[<симптом>]]
```

Блок «на будущее» (обобщённый паттерн) в `вывод.md` **не дублируется** — он живёт в
заметке симптома. `вывод.md` только линкует симптом через `[[<симптом>]]`.

## Структура `kb/Симптомы/<симптом>.md`

```markdown
---
тип: симптом
симптом: <текст>
дата_обновления: <yyyy-MM-dd>
---

# Симптом: <текст>

## Как распознать
…

## Что проверять (по порядку)
1. …

## Наблюдавшиеся причины
- **<причина>** — <когда так> → [[<sz>]]

## Связанные СЗ (авто)
​```dataview
list from "СЗ" where contains(симптом, this.file.link) sort дата desc
​```
```

Скелет (frontmatter + пустые секции + Dataview) генерит код через `EnsureSymptom`. Секцию
«Наблюдавшиеся причины» дописывает Claude при закрытии СЗ. `EnsureSymptom` идемпотентен —
существующую заметку не перетирает.

## Токен-экономный поиск

Рабочий цикл поиска при новой СЗ:

1. `Grep` по `тип: симптом` (или по ключевому слову симптома) в `kb/Симптомы/`.
2. Прочитать **одну** найденную заметку — в ней уже собраны все причины и что проверять.
3. Не читать другие СЗ: связующее звено лежит в заметке симптома, а не размазано.

Для человека в Obsidian: `MOC.md` получает секцию-индекс «Симптомы» (Dataview-список всех
заметок с `тип: симптом`).

## Изменения в коде

Проекты: `SzDiag.Kb` (основное), `SzDiag.Cli` (команды). `SzDiag.Agent`/`SzDiag.Hub` —
не затрагиваются. `ReportMarkdownBuilder` — не трогаем.

### `SzDiag.Kb/KbPaths.cs`
- `Summary(sz)` → `<sz>/вывод.md`
- `SymptomsRoot` → `Root/Симптомы`
- `SymptomNote(name)` → `Симптомы/<name>.md`

### `SzDiag.Kb/KnowledgeBaseScaffolder.cs`
- Шаблон home note расширить ключами `симптом: []`, `статус: ""`, `вердикт: ""` и секцией
  `## Вывод\n![[вывод]]` (в начале, до Дефекта — клиентский блок сверху).
- Новый метод `EnsureSummarySkeleton(sz)`: создаёт `вывод.md` с плейсхолдерами, если его
  нет; добавляет `![[вывод]]` в home note один раз (идемпотентно). Не перетирает
  существующий `вывод.md`.

### `SzDiag.Kb/EntityNoteWriter.cs`
- `EnsureSymptom(name)` — скелет заметки симптома (frontmatter + секции + Dataview),
  идемпотентно.
- `EnsureMoc` — добавить секцию «Симптомы» (Dataview `table from "" where тип = "симптом"`
  или list по папке `Симптомы`).

### `SzDiag.Kb/RecordRequest.cs` + `KbRecorder.cs`
- `RecordRequest`: добавить `Symptoms` (`IReadOnlyList<string>`), `Status` (`string?`),
  `Verdict` (`string?`).
- `KbRecorder.Record`: для каждого симптома `fm.AddToList("симптом", Quoted(s))` +
  `_entities.EnsureSymptom(s)`; `Status`/`Verdict` → `fm.SetScalar` (без кавычек-линка,
  это простые скаляры).

### `SzDiag.Cli/KbCommand.cs`
- `kb summary <sz>` — `new KnowledgeBaseScaffolder(kbRoot).EnsureSummarySkeleton(sz)`,
  печатает путь к `вывод.md`.
- `record`: новые флаги `--symptom` (many), `--status` (single), `--verdict` (single) →
  прокинуть в `RecordRequest`. Обновить usage-текст.

## Обработка ошибок

Следуем текущим конвенциям KB:
- Все `Ensure*`/скелеты идемпотентны: файл существует → не трогаем (как `WriteIfMissing`).
- Пути от `KbPaths`, санитизация имён симптомов при формировании имени файла (симптом —
  свободный текст: убрать/заменить символы, недопустимые в имени файла Windows).
- Frontmatter-мёрж через существующий `FrontmatterEditor` (тело и неизвестные ключи
  сохраняются).

## Тестирование

Зеркальные тесты в `tests/SzDiag.Kb.Tests` и `tests/SzDiag.Cli.Tests`:

- `EnsureSummarySkeleton`: создаёт `вывод.md` с обоими блоками; повторный вызов не
  перетирает; `![[вывод]]` добавляется в home note ровно один раз.
- `EnsureSymptom`: создаёт скелет с `тип: симптом`; повторный вызов не перетирает
  дописанные Claude причины.
- `KbRecorder`: `симптом`/`статус`/`вердикт` попадают в frontmatter home note; симптом
  порождает заметку в `Симптомы/`; повторная запись не дублирует список.
- Санитизация имени файла симптома со спецсимволами.
- `KbCommand`: `summary` создаёт файл; `record` с новыми флагами мёржит поля.
