# Апдейтер клиента (SzDiag.Updater) — дизайн

**Дата:** 2026-07-21
**Статус:** дизайн одобрен, ждёт план реализации

## Проблема

Обновление агента на клиенте — ручной трёхшаговый цикл: собрать `dist`, закинуть на
share, с share перетащить на клиента с заменой файлов и запустить. Больно и медленно,
особенно при частых правках агента (за одну сессию агента пересобирали и переставляли
несколько раз — план Б, ACL-фикс, пробы RunDiag, фикс PowerShellRunner). Нужен способ
разослать обновление с хоста автоматически, чтобы на клиенте ничего не таскать руками.

## Цель

Тонкий **`Updater.exe`** — точка входа на клиенте вместо прямого запуска агента. При
старте он находит hub, сверяет версию, при необходимости качает свежий пакет агента и
запускает `agent.exe`. На клиента кидается **один раз** (`Updater.exe` + `appsettings.json`
с токеном); дальше всё — agent.exe, ssh-бинарники, ключ, testsuite — тянется само.

## Ключевые решения (из брейнсторма)

- **Scope пакета:** agent.exe + мелкие файлы (ssh-бинарники, `service_key.pub`,
  `testsuite.json`, `version.txt`). **НЕ** входят: `appsettings.json` (локальный конфиг
  клиента — HubUrl/токен) и `tools/` (стресс-проги, гигабайты — раздаются отдельно, см.
  задачу упаковки тулов).
- **Поведение при старте:** требовать hub. Без связи с hub Updater не стартует (агент и
  так без hub бесполезен — регистрация и диагностика идут через него).
- **Версионирование:** строка-версия пакета (`version.txt`). Разные строки → скачать весь
  мелкий набор одним zip. Целостность zip — sha256.
- **Подход:** отдельный проект `SzDiag.Updater` (не самообновление внутри агента, не
  PowerShell-скрипт) — чистая изоляция, агент не знает про обновления.

## Поток (точка входа)

На клиенте лежат `Updater.exe` + `appsettings.json` (токен, опц. `HubUrl`). Запуск Updater:

1. **Найти hub** — `HubDiscovery` (UDP-broadcast + токен) либо явный `HubUrl` из конфига.
   Нет hub → внятная ошибка, стоп.
2. **`GET /agent/version`** (заголовок `X-SzDiag-Token`) → строка версии хоста.
3. Прочитать локальный `version.txt` (рядом с exe). Отсутствует или отличается от хостовой
   → нужно обновление.
4. **Обновление:** `GET /agent/package` → `package.zip` во временный файл → сверить sha256
   с хостовым → распаковать поверх рабочей папки, **исключая `appsettings.json` и `tools/`**
   → записать новый `version.txt`. Распаковка атомарна: во временную папку, затем замена
   файлов (не оставлять полу-обновлённое состояние при сбое).
5. **Запустить `agent.exe`** в той же консоли (без redirect stdio — агент сам интерактивно
   спрашивает СЗ, находит hub, регистрируется, как сейчас). Updater ждёт выхода агента.

**Первый заезд:** локально только `Updater.exe` + `appsettings.json` → `version.txt` нет →
Updater качает весь мелкий набор → запускает. То есть на клиент достаточно закинуть один
`Updater.exe` + конфиг с токеном.

## Транспорт (hub)

Новые эндпоинты в `SzDiag.Hub`, аутентификация `X-SzDiag-Token` (тот же `AgentToken`, что и
у агента; переиспользовать существующий agent-token middleware из `Program.cs`):

- `GET /agent/version` → строка версии, plain text (`text/plain`).
- `GET /agent/package` → `application/zip` (мелкий набор).
- `GET /agent/package.sha256` → sha256 пакета, plain text (отдельный эндпоинт — не зависит
  от кастомных заголовков ответа).

Hub раздаёт из **готовой** папки `dist/host/hub/agent-dist/{version.txt, package.zip,
package.sha256}` — hub НЕ лазит по `dist/client`, `build-dist` кладёт туда готовые артефакты.
Путь к папке раздачи — в конфиге hub (рядом с `KnowledgeBaseRoot`). Имена маршрутов — в
`HubRoutes` (единый источник имён по конвенции проекта).

## build-dist.ps1

Добавить в конце публикации клиента:

- **Версия** = `git rev-parse --short HEAD`; если рабочее дерево грязное — суффикс
  (напр. `-dirty` или timestamp); вне git — timestamp. Пишется в `dist/client/version.txt`.
- **Пакет:** заархивировать мелкий набор из `dist/client` (agent.exe, `ssh/`,
  `service_key.pub`, `testsuite.json`, `version.txt` — **без** `appsettings.json` и `tools/`)
  в `package.zip`, посчитать sha256 → `package.sha256`.
- Разложить `version.txt` + `package.zip` + `package.sha256` в `dist/host/hub/agent-dist/`.
- Собрать новый проект `SzDiag.Updater` (как и остальные компоненты, через `Publish`).
- Лаунчер клиента: точка входа для оператора — запуск `Updater.exe` (не `agent.exe`).

## Проекты и компоненты (изоляция)

**Новый `SzDiag.Updater`** (net8, self-contained single-file, console):

- `UpdateClient` — HTTP к hub: `GetVersionAsync()`, `DownloadPackageAsync()` со сверкой
  sha256. За интерфейсом (`IUpdateClient`) для юнит-тестов.
- `PackageApplier` — распаковка zip поверх рабочей папки, исключая `appsettings.json` и
  `tools/`, атомарно (temp → замена). За интерфейсом файловых операций либо с инъекцией
  корневого пути для теста.
- `AgentLauncher` — `Process.Start("agent.exe")` с наследованием консоли (без redirect),
  `WaitForExit`.
- `Program` — оркестрация потока + внятные ошибки и лог-файл рядом с exe (как у агента).

**Рефактор:** `HubDiscovery` сейчас в `SzDiag.Agent`. Вынести в общее место (в
`SzDiag.Contracts`, где уже живёт `DiscoveryProtocol`, либо в новый общий проект), чтобы
Updater и Agent делили одну реализацию, а не дублировали UDP-логику. Правка агента —
только смена namespace/using; поведение не меняется.

**Hub:** новый файл эндпоинтов (напр. `AgentPackageApi`, minimal API), регистрация в
`Program.cs`, переиспользование agent-token-фильтра.

## Обработка ошибок и edge-case

- **Hub не найден** → Updater фейлит с внятным сообщением (требовать hub).
- **Hub найден, но `/agent/*` = 404** (старый hub без апдейт-эндпоинтов) → если локальный
  `agent.exe` есть, запустить его (деградация); иначе внятный фейл («hub не поддерживает
  апдейт, обнови клиент вручную»).
- **Скачивание/sha256 не сошлись** → не заменять файлы, запустить локальный `agent.exe`
  если он есть; иначе фейл.
- **`agent.exe` залочен** (уже запущен другой сессией) → не заменять, запустить
  существующий.
- Все ошибки — в лог-файл рядом с Updater.exe (переживает закрытие окна).

## Безопасность

Клиентская машина недоверенная, хост — доверенный (модель угроз проекта). Updater качает
с hub по `X-SzDiag-Token` и проверяет sha256 пакета — достаточно для LAN-сценария.
Защита от downgrade и цифровая подпись пакета — **вне MVP**, принятый риск (доступ по LAN
+ pre-shared токен).

**Самообновление самого Updater — вне MVP.** Updater стабилен и меняется редко; при смене
протокола раздачи обновляется руками. Версия Updater закладывается в манифест на будущее,
но механизм self-replace не реализуется в первой итерации.

## Тестирование

- **Updater-юниты:** решение «качать/пропустить» по сравнению версий; `PackageApplier`
  исключает `appsettings.json`/`tools/` и применяет атомарно; sha256-верификация отвергает
  битый zip (фейковые `IUpdateClient`/файловые операции).
- **Hub (`SzDiag.Hub.Tests`):** `/agent/version` и `/agent/package` отдают контент; токен-гейт
  → 401 без `X-SzDiag-Token`.
- **build-dist:** ручная проверка — генерятся `version.txt`, `package.zip`, `package.sha256`;
  пакет не содержит `appsettings.json`/`tools/`.
- **e2e:** правка агента → `build-dist` → на клиенте Updater видит новую версию → качает →
  распаковывает → запускает свежий agent; повторный запуск без правок — версия совпадает,
  качания нет, сразу запуск.

## Вне scope (YAGNI)

- Раздача `tools/` (стресс-проги) через апдейтер — отдельная задача (упаковка тулов в
  образ/архив).
- Самообновление Updater, downgrade-защита, подпись пакета.
- Периодическая/фоновая проверка обновлений — проверка только при старте Updater.
- Дельта-обновления пофайлово (hash-манифест) — набор мал, тянем целиком.
