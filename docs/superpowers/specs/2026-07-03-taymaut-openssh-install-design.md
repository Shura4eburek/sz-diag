# Таймаут на установку OpenSSH (не виснуть без WU)

Дата: 2026-07-03

## Задача

`WindowsSystemAccessManager.Open` (первый шаг открытия доступа) вызывает
`Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0`, если службы `sshd` на
клиенте ещё нет. Этот вызов идёт через Windows Update. `PowerShellRunner.Run` не имеет
таймаута вообще (`Process.WaitForExit()` без ограничения) — если WU недоступен, агент
виснет на экране «Открываю доступ для СЗ…» бесконечно, без единого сообщения об ошибке.
Обнаружено в поле: вторая клиентская машина зависла именно на этом шаге.

Сеть сервисного центра обычно с интернетом, но иногда полностью без него — и в этом
случае у оператора и так нет доступа к внутренней шаре (`C:\Share`), т.е. полностью
офлайн-сценарий уже тупиковый для других задач. Бандлить offline-пакет OpenSSH
(`.cab`, привязан к конкретной сборке Windows) в `dist\client\` не оправдано этим редким
и всё равно нерабочим случаем.

## Решение

### `PowerShellRunner`

Новый опциональный параметр `TimeSpan? timeout` в `Run`. Если процесс не завершился за
это время — убить процесс (`Process.Kill(entireProcessTree: true)`) и выбросить новый
тип `PowerShellTimeoutException` (не путать с обычным ненулевым exit-кодом — таймаут
кидается **всегда**, независимо от `throwOnError`, поскольку это не штатный код возврата
скрипта, а признак зависшего процесса).

### `WindowsSystemAccessManager.Open`

Шаг установки OpenSSH (`Add-WindowsCapability -Online`, шаг 1) оборачивается таймаутом
**2 минуты** (константа в классе). При отлове `PowerShellTimeoutException` на этом шаге —
выбрасывается `InvalidOperationException` с понятным текстом:

> OpenSSH не ставится — нет доступа к Windows Update (истёк таймаут 2 мин). Проверьте
> интернет на клиенте и запустите агента заново.

Остальные шаги `Open`/`Revert` таймаутом не оборачиваются — они не ходят в интернет и не
имеют истории зависаний.

### `Program.cs` (агент)

По аналогии с уже существующим паттерном для `HubNotFoundException` (автообнаружение
hub'а): `session.StartAsync()` оборачивается в `try/catch` для этого сценария —
печатается чистое однострочное сообщение (`Announce`), агент завершается с кодом 1,
**вместо** попадания в общую панель «ФАТАЛ: агент упал» с полным стектрейсом.

Поскольку сообщение об OpenSSH-таймауте рождается глубоко внутри
`WindowsSystemAccessManager.Open` (вызывается синхронно из `AgentSession.StartAsync`),
а не отдельным именованным типом исключения на уровне агента — используем тот же
`InvalidOperationException`, но с этим конкретным, узнаваемым текстом. Ловим по
подстроке в `Program.cs`? Нет — вместо матчинга по тексту, заводим отдельный публичный
тип исключения `OpenSshUnavailableException` (в `SzDiag.Agent`, рядом с
`WindowsSystemAccessManager`), чтобы `Program.cs` мог поймать его по типу, как
`HubNotFoundException`. Текст сообщения хранится в самом исключении.

## Тестирование

`PowerShellRunner` до этой задачи не имел юнит-тестов вообще (использовался только через
абстракцию `ISystemAccessManager` с фейками выше по уровню). Таймаут — первый случай,
который можно проверить честно и быстро: реальный `powershell.exe -Command
"Start-Sleep -Seconds 3"` с `timeout: TimeSpan.FromMilliseconds(500)` должен упасть с
`PowerShellTimeoutException` **за заметно меньшее время**, чем 3 секунды (тест
замеряет `Stopwatch` и проверяет верхнюю границу, напр. < 2 секунд) — подтверждает, что
процесс реально убивается, а не просто помечается как "упавший" после полного ожидания.

Второй тест: команда, укладывающаяся в таймаут (`Start-Sleep -Milliseconds 100` с
таймаутом 5 секунд), должна отработать как обычно (без исключения, с нормальным
`PsResult`).

`WindowsSystemAccessManager`-специфичную логику (обёртка таймаута вокруг конкретного
шага, перевод в `OpenSshUnavailableException`) отдельным тестом не покрываем — класс и
так не тестировался (требует реальных Windows-привилегий/системных изменений), только
`PowerShellRunner`.

## Обратная совместимость

- `Run(string script, bool throwOnError = true)` — существующая сигнатура остаётся
  рабочей (новый параметр `timeout` опциональный, по умолчанию `null` = без таймаута,
  как сейчас). Все существующие вызовы `_ps.Run(...)` в `WindowsSystemAccessManager` и
  `PowerShellCommandExecutor` не меняются, кроме одного (шаг установки OpenSSH).
- Прочие шаги `Open`/`Revert` не имеют таймаута — поведение не меняется.
