# SzDiag Desk — десктопный GUI с сессиями Claude на каждую СЗ — дизайн

**Дата:** 2026-09-25
**Статус:** этапы 1–5 реализованы (планы частей 1–3), этап 6 (`ask_peer`, бейдж `≈`) — часть 4

## Проблема

Работа с живыми СЗ сейчас размазана по окнам: `szcli watch` в одном терминале, сессия
Claude Code в другом, `szcli sensors`/`reboots`/`exec --result` — руками по мере надобности.
Какая сессия Claude ведёт какую СЗ, держится в голове. Прогресса `push`/`pull` не видно вовсе:
запрос синхронный и молчит до конца. Электрон-обёртки (как у `claude-tg-bridge`) не хочется —
это браузер в окне и сотни мегабайт памяти ради списка и чата.

## Цель

Одно нативное окно на сервисном боксе, где видно:

1. слева — СЗ онлайн (с признаками здоровья);
2. в центре — чат сессии Claude, привязанной к выбранной СЗ (**строго 1 СЗ = 1 сессия**);
3. справа — выдвижной инспектор СЗ (вырубоны, сенсоры, задачи, журнал, железо, действия);
4. снизу — статусбар hub;
5. прогресс-бары передач файлов на клиента и с клиента.

Сессии Claude могут спрашивать друг друга («чо у тебя там?»), когда на соседней СЗ тестится
похожее.

**Не цель:** замена `szcli` (CLI остаётся основным инструментом и для Claude, и для человека),
работа без открытого окна (см. «Развитие»), Telegram (следующий этап, см. «Развитие»),
управление hub (старт/стоп).

## Решения и почему

| Решение | Почему |
|---|---|
| **Avalonia**, не WebView/Electron/Tauri | Рендер через Skia, без браузера: ~40–80 МБ против 150–300 МБ у WebView2. Стили CSS-подобные — macOS-вид достижим. net8.0 и общие проекты (`Contracts`, клиент hub) подключаются напрямую. |
| **Чат поверх `claude -p` в режиме stream-json**, не встроенный терминал | Это полный Claude Code (`CLAUDE.md`, скиллы, память, `szcli`, `gh` — ишью заводятся как раньше), но события структурированы: вызовы инструментов — карточки, разрешения — диалог, токены — счётчик. Тот же поток потом отдаётся в Telegram. Терминал в Avalonia = ConPTY + VT-эмулятор без зрелого контрола. |
| **GUI сам владеет сессиями**, а не подключается к чужим (модель `claude-tg-bridge`) | Для работы с SzDiag не нужно открывать IDE или терминал: у bridge-модели сессия существует, только пока жива вкладка терминала. Цена — Telegram придётся подключать к ядру `SzDiag.Claude`, а не к существующему мосту. |
| **Сессии живут в процессе GUI** (не отдельная служба, не hub) | Самое простое. Закрыл окно — процессы остановлены, разговор продолжается `--resume`. Hub — критичный канал к клиентам, падения `claude` его задевать не должны. Ядро без UI позволяет позже вынести хостинг в службу без переписывания. |
| **Опрос `/api`**, не push-канал | Hub почти не трогаем. Push добавим, если опрос станет узким местом. |
| **1 СЗ = 1 сессия + `ask_peer`** | Контекст сессии не смешивает две машины; сравнение «две идентичные сборки» (161432) идёт через вопрос соседу, а не через общую сессию. |

## Внешний вид

Утверждённый макет — вариант **B v2** (`.superpowers/brainstorm/…/layout-b-v2.html`, вне git).

- **Тёмная тема**, минимализм, macOS-стилистика: скругления 8–12 px, тонкие разделители
  (`#2a2b31`), приглушённый текст второго плана, акцент `#0a84ff` (systemBlue), статусы —
  зелёный `#30d158` / оранжевый `#ff9f0a` / красный `#ff453a` / фиолетовый `#bf5af2`
  (сессии переписываются). Шрифт — Segoe UI Variable (SF на Windows нет).
- **Свой заголовок окна** (`ExtendClientAreaToDecorationsHint`): слева «SzDiag», справа
  кнопки Windows (свернуть/развернуть/закрыть) — **тонкие глифы 1.1 px, при наведении
  скруглённая плашка** (r=6, 34×28), крестик при наведении — `#e81123` с белым глифом.
  Снэп-лейауты Win11 должны работать (hit-test на кнопке «развернуть»).
- **Раскладка:** левая колонка 210 px (СЗ) · чат (растягивается) · инспектор 290 px.
  Инспектор открывается/скрывается **кнопкой-иконкой справа в шапке чата** (иконка
  «sidebar.right»; открыт — подсвечена акцентом). Горячей клавиши не делаем. Состояние
  инспектора запоминается.
- **Карточка СЗ:** точка статуса (онлайн / лаг heartbeat / вероятный вырубон / офлайн),
  номер, железо одной строкой (CPU · плата), бейджи `⚡N` (вырубоны), `🧊` (freeze),
  `≈<СЗ>` (похожая СЗ в работе).
- **Лента чата:** реплики Claude — текст (markdown: код, списки, таблицы), свои — синие
  пузыри справа, вызовы инструментов — свёрнутые моно-карточки `✓ команда · 12с`
  (раскрываются в полный вывод), разрешения — оранжевая карточка с кнопками, вопросы от
  соседа — `💬 от 161501: …`, системные события машины — серые строки.
- **Статусбар:** hub (версия, `/healthz`), версия пакета агента, последний бэкап kb,
  туннель, токены за сегодня по всем сессиям.

## Архитектура

### Проекты

| Проект | Что внутри | Зависит от |
|---|---|---|
| `SzDiag.Desk` (новый, WinExe) | Avalonia-приложение: окна, контролы, ViewModel'и (CommunityToolkit.Mvvm), опрос hub | `SzDiag.Claude`, `SzDiag.HubClient`, `SzDiag.Contracts`, `SzDiag.Kb` |
| `SzDiag.Claude` (новый, lib) | Ядро сессий без UI: процесс `claude`, парсер stream-json, менеджер сессий, MCP-сервер | — (только BCL + MCP SDK) |
| `SzDiag.HubClient` (новый, lib) | `HubApiClient`/`IHubApiClient`, вынесенные из `SzDiag.Cli` | `SzDiag.Contracts` |
| `SzDiag.Cli` | переходит на `SzDiag.HubClient` | + `SzDiag.HubClient` |
| `SzDiag.Hub` | + `GET /api/transfers` | — |

`SzDiag.Claude` не знает про СЗ как предметную область — ключ сессии для него строка.
Всё про СЗ (вводная, выжимка kb для `ask_peer`, похожесть железа) приходит извне через
интерфейсы, реализованные в `SzDiag.Desk`. Это оставляет ядро пригодным для Telegram и
для будущей службы.

### `SzDiag.Claude`

- **`ClaudeProcess`** — запуск и ввод-вывод одного процесса:
  ```
  claude -p --input-format stream-json --output-format stream-json --verbose
         [--resume <session_id>]
         --append-system-prompt "<вводная>"
         --mcp-config <json с адресом /mcp/<ключ> и токеном>
         --permission-prompt-tool mcp__desk__permission_prompt
         --permission-mode <PermissionMode>
  ```
  Режим — `PermissionMode` конфига Desk, по умолчанию **`auto`**, как у терминального Claude:
  разрешения спрашиваются только на то, что не пропустил классификатор, иначе оператор
  подтверждал бы каждый шаг. `default` — карточка на каждый инструмент. Режим передаётся
  явно всегда (спайк: без флага действует режим из настроек профиля). В `--mcp-config` у сервера `desk` — поле
  `timeout` (мс): без него `claude` обрывает тулзу после 300 с молчания, а разрешение ждёт
  человека сколько угодно. См. [итоги спайка](2026-09-25-desk-spike-notes.md).
  Рабочий каталог — корень репозитория sz-diag (чтобы подхватились `CLAUDE.md`,
  `.claude/settings.json`, скиллы, память). Путь к `claude` — из конфига, по умолчанию
  поиск в `PATH`. Сообщения пользователя пишутся в stdin как NDJSON-строки; stdout читается
  построчно; stderr копится в кольцевой буфер (последние 200 строк) для диагностики падения.
  **Профиль Claude выбирается на заявку.** Профили не прописываются, а ищутся: каталоги
  `.claude*` в домашней папке, где есть вход (`.credentials.json`) — на боксе `claude`
  (`~/.claude`) и `claude2` (`~/.claude2`, его поднимает обёртка `claude2.cmd`). «Начать
  сессию» — кнопка на каждый профиль; профиль записывается в `desk-sessions.json` и
  закрепляется за разговором (`CLAUDE_CONFIG_DIR` процесса и скрипта «открыть в терминале»):
  разговор лежит в каталоге профиля, `--resume` из другого его не найдёт. Профиль по умолчанию
  (`~/.claude`) — это снятая переменная, а не унаследованная от запустившего Desk. Маркеры родительской сессии Claude
  (`CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_MESSAGING_*` и т.п.) из окружения процесса
  вычищаются: иначе Desk, запущенный из-под Claude, выключал бы детям запись транскрипта.
- **`StreamJsonParser`** — строка → типизированное событие: `SystemInit` (`session_id`,
  модель, инструменты; приходит **на каждый ход**, не раз на процесс), `AssistantText`, `ToolUse`, `ToolResult`, `Result` (итог хода:
  токены, стоимость, длительность), `Unknown` (сырой JSON — не теряется). Битая строка —
  пропуск + лог.
- **`ClaudeSession`** — состояние одной сессии: `Idle` / `Working` / `WaitingPermission` /
  `AnsweringPeer` / `Crashed` / `Archived`; очередь исходящих сообщений (отправка, пока
  сессия занята, — «в очереди»); лента событий; счётчик токенов.
- **`SessionManager`** — правило «1 ключ = 1 сессия», реестр `ключ → session_id` в
  `desk-sessions.json` рядом с exe, ленивое поднятие с `--resume` при открытии чата,
  корректная остановка всех процессов при выходе.
- **`DeskMcpServer`** — MCP-сервер (официальный C# SDK `ModelContextProtocol.AspNetCore`,
  streamable HTTP) на `127.0.0.1:<случайный порт>`, токен генерируется на запуск Desk.
  У каждой сессии свой путь `/mcp/<ключ>` — сервер знает, кто зовёт. Инструменты:
  - `permission_prompt(tool_name, input)` → ждёт решения человека в GUI → `allow`/`deny`;
  - `peers()` → список других активных сессий с кратким профилем (через `IPeerDirectory`);
  - `ask_peer(key, question)` → ответ соседа (см. ниже).

### `ask_peer`

1. Сначала `IPeerDirectory.Summary(key)` — выжимка из `kb/СЗ/<сз>/діагностика.md` и
   хвоста `журнал.md` (без токенов, без отвлечения соседа). Возвращается вместе с флагом
   «спросить живьём?», если выжимки не хватает — это решает спрашивающий Claude повторным
   вызовом с `live: true`.
2. Живой вопрос встаёт в очередь соседа и отправляется ему в stdin, когда тот `Idle`,
   с префиксом `[вопрос от сессии <ключ>] …`. Сосед переходит в `AnsweringPeer`; его
   финальный текст хода возвращается спросившему.
3. Ограничения: **глубина 1** (у сессии в `AnsweringPeer` `ask_peer` возвращает ошибку),
   **20 живых вопросов в час** на спрашивающего, **таймаут 5 минут**. Все три — в конфиге.
4. В GUI вопрос и ответ видны в обеих лентах; в списке СЗ у пары — фиолетовая метка.

**Похожие СЗ** (`≈`): совпадение CPU, платы или профиля/частоты памяти по `hw passport`
(кэшируется в Desk). Бейдж — подсказка человеку; Claude видит то же через `peers()`.

### Изменения в hub: `GET /api/transfers`

Сейчас `push`/`pull` — долгий синхронный запрос, прогресса нет ни у CLI, ни у GUI.
`PushCoordinator`/`PullCoordinator` регистрируют передачу в новом `TransferTracker`
(in-memory): СЗ, направление, инструмент/путь, байт всего/передано, скорость, начало,
статус (`running`/`done`/`failed` + причина). Завершённые держатся 10 минут. Эндпоинт
отдаёт список. Так прогресс виден и для передач, запущенных Claude через `szcli`, а не
только из GUI. DTO — в `SzDiag.Contracts`.

Для `push` байты считает агент (он качает с hub) — прогресс берётся из отдачи файлов в
`ToolsApi` по токену агента; для `pull` — из приёма чанков в `PullCoordinator`.

### Источники данных GUI

| Что | Откуда | Частота |
|---|---|---|
| список СЗ, статусы, uptime, `⚡N` | `/api/sessions` | 2 с |
| передачи | `/api/transfers` | 1 с, пока есть `running`; иначе 5 с |
| статусбар | `/healthz`, `/api/version` | 10 с |
| вырубоны (таймлайн) | `/api/sessions/{sz}/reboots` | при открытии + при смене `⚡N` |
| задачи | `/api/sessions/{sz}/exec` (+ `exec/{id}?tail=` для раскрытой) | 3 с, пока вкладка открыта |
| сенсоры | синхронный exec хвоста `C:\OCCT\sensors.csv` (`SensorPaths.LhmCsv`); «не пишутся» — последняя строка не менялась 30 с по часам **бокса** (часы клиента в WinPE сдвинуты) | 5 с, пока вкладка открыта |
| журнал | `kb/СЗ/<сз>/журнал.md` с диска (`KbPaths`), `FileSystemWatcher` | по изменению |
| железо | `szcli hw passport` подпроцессом, кэш на СЗ | при первом открытии, кнопка «снять заново» |

Опрос вкладок инспектора идёт **только пока вкладка видна** — под нагрузкой exec-канал
клиента и так узкий.

### Действия инспектора

`diag run` (выбор секций, `DiagSections`), `test run --config` (метка обязательна, как в
CLI), `freeze`/`unfreeze`, заметка (`note`), `sz fetch`, `close` (с выводом итога отката).
Действия и паспорт железа — **подпроцессом `szcli`** (`SzcliRunner`, `cli\SzDiag.Cli.exe` рядом
с `szcli.cmd`, `NO_COLOR=1`): `freeze` хранит прежние значения рядом с szcli (и `unfreeze` из
терминала должен их найти), у `close` свои защиты (`--force "причина"`), у `sz fetch` своя
сессия захвата — вторая реализация в Desk разошлась бы с первой. Вывод показывается как есть,
журнал СЗ ведёт hub. Разрушительные действия (`close`, `close --force`, `unfreeze`) — с
подтверждением.

## Жизненный цикл сессии

- **Старт** — кнопка «Начать сессию» на СЗ без сессии. Автостарта нет (токены).
- **СЗ офлайн** (вырубон/ребут) — сессия не трогается; в ленту — системная строка
  «машина пропала / вернулась (boot сменился)».
- **СЗ закрыта** — сессия → `Archived` и переезжает в секцию «АРХИВ» под списком заявок;
  архив открывается на чтение, продолжение — `--resume`. В архив уходит только СЗ, которая
  была в списке hub и пропала: продолженный из архива разговор следующий опрос не трогает.
- **Закрытие Desk** — stdin закрывается, процессы получают время на выход, потом kill.
- **Запуск Desk** — сессии не поднимаются; процесс стартует с `--resume` при первом сообщении
  (открытие чата только показывает ленту из журнала `sessions\<ключ>.jsonl` рядом с exe:
  `--resume` историю в stdout не повторяет).
- **Очередь** — у Desk: следующее сообщение уходит после `result` текущего хода; «■»
  возвращает неотправленное в поле ввода.
- **Стоп** — кнопка «■» прерывает текущий ход control-запросом `interrupt` stream-json-
  протокола (подтверждено спайком: процесс остаётся жив, ход закрывается `result` с
  `terminal_reason: aborted_streaming`, следующее сообщение идёт в тот же процесс).
- **Кнопка «открыть в терминале»** — `wt claude --resume <session_id>` (процесс в Desk
  перед этим останавливается, чтобы не было двух писателей в одну сессию).

## Ошибки

| Ситуация | Поведение |
|---|---|
| hub не отвечает | статусбар красный «hub не отвечает, повтор через N с»; список СЗ заморожен с «данные на ЧЧ:ММ»; сессии Claude работают дальше |
| `claude` не найден / не залогинен / упал | карточка в ленте с последними строками stderr и кнопкой «перезапустить с `--resume`»; остальные сессии не затронуты |
| битая строка stream-json | пропуск + лог; неизвестный тип — серая свёрнутая карточка `raw` |
| разрешение без ответа | ждём бесконечно, как терминал; окно мигает в панели задач сразу и каждые 10 минут, пока запрос висит (нативных уведомлений у Avalonia 11 нет) |
| сенсоры не пишутся | «сенсоры не пишутся» + кнопка `sensors start`; пустой график не рисуется |
| `ask_peer` превысил лимит / таймаут / глубину | ошибка инструмента с причиной — Claude видит её и решает сам |

Лог — `logs\desk-<дата>.log` рядом с exe, по образцу `HubLog` (чистка старше 14 дней).

## Этапы

1. **Спайк stream-json** (одноразовый код): запуск, фикстуры событий, `--permission-prompt-tool`
   с MCP по HTTP, прерывание хода, поведение `--resume`. Итог — фикстуры + подтверждение
   или правка раздела «Жизненный цикл».
2. **`SzDiag.HubClient`** (вынос из CLI) + **`/api/transfers`** в hub.
3. **Окно Desk:** заголовок и кнопки окна, список СЗ, статусбар, панель передач.
4. **`SzDiag.Claude` + чат:** сессии, лента, разрешения, очередь, стоп, `--resume`.
5. **Инспектор:** вкладки и действия.
6. **`ask_peer` + похожие СЗ.**

Каждый этап — рабочий результат: после этапа 3 Desk уже заменяет `szcli watch`.

## Развитие (вне scope)

- **Telegram** — лента и карточки разрешений из `SzDiag.Claude` в чат; подтверждение с
  телефона. Возможно, через адаптер к `claude-tg-bridge` (мини-аппа уже умеет рисовать
  ленту) или своим ботом — решается отдельной спекой.
- **Сессии без окна** — вынос `SessionManager` в службу, Desk и Telegram становятся её
  клиентами.
- **Push-канал hub → Desk** (SignalR) вместо опроса.
- **Кнопка «⚑ ишью»** на карточке ленты — готовый контекст (команда, вывод, СЗ) в сессию
  для оформления ишью. В первой версии ишью заводит Claude через `gh`, как сейчас.
