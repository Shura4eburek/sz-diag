# Точечный запуск тестов + столбик «Активность»

Дата: 2026-07-03

## Задача

Оператор системы — Claude, работающий через `szcli`. Нужны две вещи:

1. **Точечный запуск тестов.** Не всегда нужен полный цикл `testsuite.json` (минуты
   ожидания). Дать возможность запустить конкретный тест/подмножество (например только
   OCCT). Всё read-only (журнал событий, `systeminfo`, файлы) оператор делает напрямую по
   SSH (`svc-diag@<ip>` — локальный админ), кода это не требует; в коде закрываем только
   выборочный запуск тяжёлых стресс-тулов, которым нужен elevated-агент + рабочий стол +
   бандл в `tools\`.
2. **Столбик «Активность».** В таблице онлайн-СЗ (`szcli watch`/`list`) показывать, что
   прямо сейчас происходит на машине: `Тест OCCT 5мин 44сек` с тикающим временем.

## Ключевое решение: `Id` у шага

Обе фичи опираются на короткий идентификатор шага, которого сейчас нет. В `TestStep`
добавляется поле `Id` (слаг: `occt`, `tm5`, `furmark`, `3dmark`). По нему выбирается шаг
для запуска и строится короткая метка активности («Тест OCCT»). Полное `Name` («OCCT —
комбинированный + Power (расписание…)») для столбика и селектора слишком длинное.

`testsuite.json` бэкфиллится: каждому шагу проставляется `id`.

## Фича 1 — точечный запуск тестов

### Протокол

`RunTests(sz)` → `RunTests(sz, filter)`:

- `filter` — список id через запятую (`"occt"`, `"tm5,furmark"`).
- Пусто/`null` = весь набор (обратная совместимость: старый вызов `test run <СЗ>` без
  аргумента не ломается).

Цепочка проброса:
`HubRoutes.RunTests` → `SignalRAgentCommandSender.SendRunTestsAsync(connId, sz, filter)`
→ `TestRunTrigger.TriggerAsync(sz, filter)` → `ManagementApi`
(`POST /api/sessions/{sz}/test?filter=occt`) → `HubApiClient.TriggerTestAsync(sz, filter)`
→ CLI.

### Агент

`TestReportRunner.RunAndUploadAsync(sz, filter)` фильтрует `suite.Steps` по `Id`
(регистронезависимо):

- фильтр выбрал шаги → гоним подмножество, заливаем как обычный отчёт (просто по меньшему
  числу шагов);
- фильтр ничего не выбрал → агент печатает
  `не найдено шагов по фильтру 'X'. Доступные: occt, tm5, furmark, 3dmark`
  и **ничего не гоняет** (пустой отчёт не заливается).

### CLI

```
szcli test run <СЗ>              # весь набор (как сейчас)
szcli test run <СЗ> occt         # только OCCT
szcli test run <СЗ> tm5,furmark  # подмножество
```

`test list` не делаем (YAGNI): id известны из репозитория, а при опечатке агент сам
выведет доступные.

## Фича 2 — столбик «Активность»

### Отображаемые состояния

| Ситуация | Текст |
|---|---|
| Идёт тест | `Тест OCCT 5мин 44сек` (время тикает) |
| Простой, есть история | `готов · последний: TM5 ✓` (✓ все шаги чисто / ⚠ были ошибки/предупреждения) |
| Простой, истории нет | `— готов` |
| Offline | `—` |

### Вычисление времени

Агент шлёт наверх пару `(label, sinceUtc?)`. «5мин 44сек» **вычисляет CLI** от `sinceUtc`
до `now`. Плюсы: секунды тикают плавно (watch и так рефрешит раз в секунду), heartbeat не
спамится — активность пушится только на **смену** состояния (старт шага / конец шага /
конец прогона / коннект).

- Идёт тест: `label="Тест OCCT"`, `since=startedAt` → CLI дописывает elapsed.
- Простой с историей: `label="готов · последний: TM5 ✓"`, `since=null`.
- Простой без истории: `label="— готов"`, `since=null`.

### Протокол

Новый метод агент→hub: `ReportActivity(sz, label, sinceUtc?)`.

- `HubRoutes.ReportActivity`
- `IHubLink.ReportActivityAsync(...)` + реализация в `SignalRHubLink`
- `AgentHub.ReportActivity(...)` → `SessionRegistry.SetActivity(sz, label, since)`
- `SessionInfo` получает два поля: `Activity` (string), `ActivitySince`
  (`DateTimeOffset?`). Дефолты — пустая строка / `null`, чтобы не ломать существующие
  конструкторы/тесты и сериализацию.

### Источник метки

В `TestRunner.Run` добавляется опциональный колбэк прогресса `Action<string?>` (имя шага
при старте шага, `null` по завершении шага). `TestReportRunner` передаёт колбэк, который
пушит активность в hub (fire-and-forget SignalR-вызов; сам прогон уже крутится на
`Task.Run`). После прогона агент ставит idle-метку с итогом `✓/⚠` (по наличию
Error/предупреждений в `output.Report.Steps`). При коннекте/реконнекте агент пере-пушивает
текущее состояние (стартовое — `— готов`).

Короткая метка теста строится из `Id` шага: `Тест {Id.ToUpper}` (fallback — усечённое
`Name`, если `Id` пуст).

### CLI

`SessionTableRenderer` получает 5-й столбец «Активность»:

- `ActivitySince != null` → к `Activity` дописывается гуманизированный elapsed
  (`44сек` / `5мин 44сек` / `1ч 05мин`), красится жёлтым/зелёным (идёт тест);
- иначе печатается `Activity` как есть;
- offline-строка → `—`.

Форматтер elapsed — отдельный чистый метод (легко тестируется): <1 мин → `Nсек`;
<1 ч → `Mмин SSсек`; ≥1 ч → `Hч MMмин`.

## Тестирование (TDD)

Юнит-тесты:

- `SessionRegistry.SetActivity` — сохраняет label+since, отражается в `GetActive()`;
  `Register` ставит дефолтную активность; heartbeat/offline не затирают активность
  неожиданно.
- Фильтрация шагов в раннере/ранере отчётов: по id; пустой фильтр = все; несуществующий
  id = пусто (ничего не гоняем).
- Форматтер elapsed: границы (59с, 60с, 3599с, 3600с).
- Рендер нового столбца `SessionTableRenderer`: online с тестом, простой с историей,
  offline.
- Проброс `filter` через `TestRunTrigger` / `ManagementApi` / `HubApiClient`.

## Обратная совместимость

- `test run <СЗ>` без фильтра = весь набор.
- Новые поля `SessionInfo` имеют дефолты (не ломают существующие тесты/JSON).
- `RunTests` со вторым аргументом — агент и хаб обновляются синхронно (один деплой).
