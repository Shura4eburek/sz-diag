# Итоговый вывод по СЗ + база паттернов симптомов — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить в KB итоговый вывод по СЗ (`вывод.md`: клиентский блок + технический разбор) и накопительную базу паттернов `Симптомы/`, ключуемую симптомом, с кодом для генерации скелетов и мёржа frontmatter.

**Architecture:** Гибрид — код (`SzDiag.Kb`) генерит скелеты с плейсхолдерами и мёржит frontmatter в единый home note `<sz>.md`; содержательную прозу вписывает Claude. `вывод.md` — прозовая заметка без своего YAML, встраивается в home note через `![[вывод]]` (единый источник истины для Dataview). Заметки симптомов идемпотентны, копят причины по всем СЗ в одной точке.

**Tech Stack:** C# / net8.0, xUnit. Файлы редактируются существующими примитивами: `FrontmatterEditor`, `KnowledgeBaseScaffolder`, `EntityNoteWriter`, `KbRecorder`.

**Отклонения от спеки (осознанные):** имена симптомов не санитизируются (консистентно с `Дефект/Компонент`); `![[вывод]]` живёт в шаблоне home note, а не домутируется; `дата_обновления` симптома — пустой плейсхолдер. `KbCommand` — тонкий парсер, отдельными юнит-тестами не покрывается (в проекте нет `KbCommandTests`); его логика проверяется через покрытые `Kb`-примитивы + ручную сборку.

    public string EnsureSummarySkeleton(string sz)
    {
        EnsureSkeleton(sz);
        var path = _paths.Summary(sz);
        WriteIfMissing(path, SummaryNote(sz));
        return path;
    }

        $"""

        ---

        ## 🔧 Технический разбор
        *для сервиса и обучения — клиенту не отдаётся*

        **Симптом (со слов клиента):** …

        **Показания диагностики:**
        - …
        - 🔗 сырой прогон: [[report]]

        **Рассуждение:** …

        **Диагноз:** …
