# sz-diag Фаза 2 — дизайн: автоматизация базы знаний + поиск

> Дата: 2026-07-01. Статус: согласовано с пользователем.
> Опирается на: [2026-07-01-kb-obsidian-design.md](2026-07-01-kb-obsidian-design.md),
> реализованную Фазу 1.

## Цель

Дать инструменты для наполнения базы знаний по СЗ структурированными данными
(дефект / находки / замены / заказ / устройство) и для поиска по прошлым СЗ, чтобы
переиспользовать опыт на новых заявках.

Модель — **гибрид**: запись и часть поиска — через CLI (`szcli kb …`), которым при
диагностике рулит Claude; визуальный просмотр по фасетам (дефект/компонент/устройство) —
в Obsidian через Dataview и граф. Структурированный CLI-поиск — по номеру заказа;
свободный текстовый поиск — по содержимому заметок.

## Границы

**В Фазе 2:** библиотека `SzDiag.Kb`, команды `szcli kb record` и `szcli kb search`,
автосоздание связуемых заметок, Dataview/MOC-шаблоны в vault.
**Не в Фазе 2:** структурированный CLI-поиск по дефекту/компоненту/устройству (это
делается визуально в Obsidian); тест-раннер и отчёты со скринами (Фаза 3).

## Где живёт и как устроено

`szcli` работает на сервисном хосте рядом с `kb/` и пишет/читает **локальную файловую
систему vault напрямую** — hub не задействован. Новый параметр в конфиге CLI: `KbRoot`
(корень Obsidian-vault, тот же, что `KnowledgeBaseRoot` у hub).

Логика базы знаний выносится в новую библиотеку **`SzDiag.Kb`** (парсинг/правка
frontmatter, автосоздание заметок, запись, поиск) — тестируемо и переиспользуемо.
`KnowledgeBaseScaffolder` **переносится** из `SzDiag.Hub` в `SzDiag.Kb`; hub начинает
ссылаться на `SzDiag.Kb`. Так вся логика КЗ оказывается в одном месте.

### Компоненты (файлы)

```
src/SzDiag.Kb/               (новая библиотека)
  KbPaths.cs                 — пути: СЗ/<n>/, <n>.md, Заказы/, Дефекты/, Компоненты/, Устройства/
  FrontmatterEditor.cs       — чтение/правка YAML-frontmatter home-заметки (лёгкий, формат наш)
  KnowledgeBaseScaffolder.cs — ПЕРЕНОС из SzDiag.Hub (каркас папки СЗ)
  IKnowledgeBaseScaffolder.cs — ПЕРЕНОС из SzDiag.Hub
  EntityNoteWriter.cs        — автосоздание связуемых заметок (Заказы/Дефекты/Компоненты/Устройства)
  KbRecorder.cs              — merge-логика record
  KbSearcher.cs              — поиск по заказу и свободному тексту
  KbSearchResult.cs          — DTO результата поиска (СЗ + краткое резюме)
src/SzDiag.Hub/              — ссылается на SzDiag.Kb; свои файлы scaffolder удаляются
src/SzDiag.Cli/              — тонкие команды kb record/search; ссылается на SzDiag.Kb
tests/SzDiag.Kb.Tests/       — юниты recorder/searcher/frontmatter/entity на temp-каталогах
```

## Команда `szcli kb record <СЗ>` (merge)

Все флаги опциональны; команда идемпотентно накапливает данные:

```
szcli kb record 156864 --order A-2025-0098 --device "Lenovo IdeaPad 3" \
  --defect "Не стартует POST" --replaced "Kingston A400 240GB" \
  --finding "POST не проходит, нет видеосигнала" --action "Заменён SSD"
```

Поведение:
- если папки `СЗ/156864/` ещё нет — создаётся каркас (через перенесённый scaffolder);
- **frontmatter** `156864.md`: `заказ` и `устройство` — перезапись (последнее значение);
  `дефект[]` и `заменено[]` — дополнение как wikilinks, без дублей;
- **автосоздание связуемых заметок**, если отсутствуют: `Заказы/A-2025-0098.md`,
  `Устройства/Lenovo IdeaPad 3.md`, `Дефекты/Не стартует POST.md`,
  `Компоненты/Kingston A400 240GB.md` (минимальный шаблон с заголовком);
- **проза** `--finding`/`--action` дописывается в `findings.md`/`actions.md` строкой с
  датой (`- YYYY-MM-DD: текст`);
- повторный вызов с теми же значениями ничего не дублирует (идемпотентность списков и
  повторной вставки строк прозы по точному совпадению за текущую дату).

Флаги `--defect`, `--replaced`, `--finding`, `--action` допускают многократное указание.

## Команда `szcli kb search`

```
szcli kb search --order A-2025-0098        # все СЗ по заказу (история обращений)
szcli kb search --text "не стартует post"  # свободный текст по заметкам СЗ
```

- `--order <n>`: находит СЗ, у которых во frontmatter `заказ` ссылается на этот заказ.
- `--text <строка>`: регистронезависимый поиск подстроки по содержимому `<n>.md`,
  `request.md`, `findings.md`, `actions.md`.
- фильтры комбинируются (AND).
- вывод: список найденных СЗ, по каждой — номер, заказ, дефект(ы), что заменено (кратко).

## Dataview/MOC-шаблоны (просмотр человеком в Obsidian)

Кладутся один раз как заготовки в vault; наполняются автоматически по мере `record`:
- в заметке **Заказа** — Dataview-таблица всех его СЗ;
- в заметке **Компонента** — по каким СЗ менялся;
- в заметке **Дефекта** — похожие случаи и что помогло;
- `MOC.md` — «Последние СЗ», «Топ дефектов», «Что чаще меняем».

Шаблоны сущностей (`EntityNoteWriter`) при автосоздании включают соответствующий
Dataview-блок, чтобы заметка сразу была полезной.

## Frontmatter: формат и правка

Формат наш (генерируем сами), поэтому `FrontmatterEditor` — лёгкий: парсит блок между
`---`, читает/пишет известные ключи (`сз`, `заказ`, `дефект`, `заменено`, `устройство`,
`дата`). Списки — YAML-массивы wikilink-строк (`дефект: ["[[…]]"]`). Правка сохраняет
неизвестные ключи и тело заметки без изменений. Свой парсер (без внешней зависимости),
т.к. набор ключей фиксирован.

## Обработка ошибок

- `record`/`search` с несуществующим `KbRoot` — понятная ошибка (проверка пути).
- `record` для новой СЗ создаёт каркас; для существующей — только дополняет, не
  перетирает прозу и данные диагностики.
- Повторный `record` идемпотентен (списки без дублей).
- `search` без совпадений — печатает «ничего не найдено», код возврата 0.

## Тестирование

Юниты `SzDiag.Kb` на временных каталогах:
- `FrontmatterEditor`: чтение, перезапись скалярных полей, дополнение списков без дублей,
  сохранение тела и неизвестных ключей.
- `EntityNoteWriter`: создаёт отсутствующую заметку, не перетирает существующую.
- `KbRecorder`: создание каркаса при отсутствии, merge frontmatter, дозапись прозы с
  датой, идемпотентность повторного вызова.
- `KbSearcher`: поиск по заказу, по тексту, комбинация, пустой результат.
- Регресс: существующие тесты hub после переноса scaffolder остаются зелёными.

CLI-команды `kb record/search` — тонкие обёртки; 1-2 smoke против temp-vault.
