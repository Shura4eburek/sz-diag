# sz-diag — Фаза 1: дизайн-спека

> Дата: 2026-07-01. Статус: согласовано с пользователем, готово к плану реализации.
> Общий замысел и фазирование: см. [../vision.md](../vision.md).

## Цель Фазы 1

Дать рабочий SSH-workflow диагностики клиентских машин по номеру СЗ:
оператор запускает агента на клиентской машине, вводит номер СЗ, машина «светится»
в центральном CLI, после чего Claude с чистого сервисного бокса заходит на неё по SSH.
После закрытия СЗ на клиентской машине не остаётся следов.

## Границы

**В Фазе 1:** агент, центральный демон (hub), CLI, каркас папок базы знаний.
**Не в Фазе 1 (направление на будущее):** автоматизация записи в базу знаний с
поиском по прошлым СЗ (Фаза 2); тест-раннер и отчёты со скринами (Фаза 3).

## Стек

.NET / C#. Агент — self-contained single-file `.exe` (без установки рантайма на
клиента). Hub и CLI — .NET-приложения на сервисном хосте.

## Компоненты

### sz-agent (клиентская машина)

Один **интерактивный** консольный exe. Помечен манифестом
`requestedExecutionLevel=requireAdministrator` → при запуске поднимает UAC.
**Без аргументов командной строки.**

Поток работы:

1. Двойной клик → UAC → приглашение `Введите номер СЗ:`.
2. Валидация ввода (номер СЗ).
3. **Открытие доступа:**
   - установить/включить OpenSSH Server (запомнить, ставил ли сам — для корректного
     отката);
   - правило firewall на порт SSH;
   - `HKLM\...\Policies\System\LocalAccountTokenFilterPolicy = 1` (полный токен для
     локального админа при сетевом логоне);
   - создать локального администратора `svc-diag`;
   - положить в `authorized_keys` пользователя `svc-diag` **публичный** ключ сервиса
     (зашит в бинарь агента);
   - зарегистрировать scheduled-task **watchdog** (авто-revert через N часов).
4. Подключиться к `sz-hub`, отправить `{СЗ, IP, hostname}`, слать heartbeat.
5. Показать живой статус-экран: `СЗ 156864 — доступ открыт ● online, IP: x.x.x.x`
   и пункт `[C] Закрыть СЗ и откатить`.
6. Пока сессия открыта — агент резидентен, держит соединение с hub и слушает команду
   `revert`.

**Закрытие / revert** (идемпотентно, безопасно при повторном вызове) — триггеры:
- локально: пункт `[C]` на статус-экране;
- централизованно: `sz-cli close <СЗ>` → hub пушит `revert` агенту;
- при закрытии окна консоли: перехват события (`SetConsoleCtrlHandler`) → попытка
  graceful revert;
- watchdog: scheduled-task по таймауту.

Revert откатывает всё: удаляет `svc-diag` и его профиль, чистит `authorized_keys`,
убирает firewall-правило, отключает OpenSSH (только если агент сам его включал),
снимает watchdog-task, дерегистрируется в hub. Результат — на машине ноль следов.

### sz-hub (сервисный хост)

Демон. Задачи:
- принимает постоянные TLS-подключения агентов (pre-shared токен, чтобы посторонняя
  машина не спамила реестр);
- ведёт реестр активных СЗ: `СЗ → {IP, hostname, status, connected-since}`;
- помечает СЗ `offline` при пропаже heartbeat’ов;
- умеет пушить агенту команду `revert` (по тому же постоянному соединению);
- персистит состояние в SQLite-файл (активные сессии + история открытий/закрытий);
  живые соединения держит в памяти, снапшот — для переживания рестарта;
- предоставляет интерфейс для `sz-cli`.

### sz-cli (сервисный хост)

Консоль/TUI, общается с hub:
- живой список онлайн-СЗ со статусом (`156864 ● online  10.0.0.42  15:30`);
- `close <СЗ>` — инициировать revert на агенте;
- `target <СЗ>` — выдать SSH-адрес/строку подключения по номеру СЗ (маршрут для Claude).

### kb/ (база знаний, Obsidian-vault — каркас)

`kb/` — Obsidian-vault. Полный дизайн: [2026-07-01-kb-obsidian-design.md](2026-07-01-kb-obsidian-design.md).

При открытии СЗ hub создаёт каркас нужной формы:

```
kb/СЗ/156864/
  156864.md     — home-заметка (frontmatter с автозаполненной датой + связи)
  request.md    — дефект со слов клиента
  findings.md   — что обнаружила диагностика
  actions.md    — что заменили/сделали
  logs/         — сырые выводы диагностики
```

В Фазе 1 — только каркас с шаблонными файлами Obsidian-формы; структурированное
наполнение, Dataview-запросы и шаблоны — Фаза 2.

## Использование Claude (диагностика)

Claude работает на чистом сервисном боксе под рабочим аккаунтом (токен на клиента не
заезжает). Берёт адрес по номеру СЗ (`sz-cli target 156864`) и заходит
`ssh -i <service_key> svc-diag@<IP>`. Приватный service-ключ — только на боксе.

По SSH в Windows доступно: реестр (r/w), логи событий, файлы, службы, процессы,
задачи. Ограничение — нет GUI. Нюанс `HKCU`: в SSH-сессии это куст `svc-diag`, а не
интерактивного юзера клиента; для правки куста клиента — `reg load`.

## Модель угроз (напоминание)

- Клиентская машина — наименее доверенное устройство, часто заражена. Claude ходит на
  неё «на расстоянии вытянутой руки» по SSH; рабочий токен на ней не появляется.
- Приватный service-ключ живёт только на чистом боксе; риск ограничен окном, когда SSH
  открыт (только на время активной СЗ).
- Малварь может врать диагностике даже по SSH → проверка на заражённость подтверждается
  офлайн-скан / загрузкой с чистого носителя. Отдельная задача, вне Фазы 1.

## Обработка ошибок

- Revert идемпотентен — три независимых триггера (CLI / локально / watchdog) не мешают
  друг другу.
- Если установка OpenSSH или создание учётки падает — агент откатывает уже сделанное и
  показывает оператору ошибку.
- Hub переживает рестарт (состояние в SQLite); при потере соединения с агентом —
  СЗ `offline`, но на клиенте watchdog всё равно откатит по таймауту.

## Тестирование

- Юнит-тесты: логика `revert` (идемпотентность), протокол реестра hub.
- Интеграция: `agent↔hub` (регистрация, heartbeat, push-revert) на одноразовой ВМ —
  агент меняет системное состояние, поэтому только на ВМ.
- Ручная проверка: реальный `ssh svc-diag@<ip>` после открытия; чистота машины после
  закрытия (нет `svc-diag`, правила firewall, ключа, watchdog-task).

## Целевое окружение

Клиенты и хост — Windows 10 1809+ / Windows 11 (встроенный OpenSSH Server). Агент
требует прав администратора.

## Открытые технические вопросы для этапа плана (не блокеры дизайна)

- Конкретный транспорт `agent↔hub` (gRPC bidi-стрим vs SignalR/WebSocket vs TLS-TCP) —
  выбрать при написании плана; требование — постоянное соединение с server-push.
- Значение таймаута watchdog (N часов) по умолчанию.
