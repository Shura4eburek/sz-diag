# Живой чек-лист: `szcli sz fetch` (2026-09-02)

Требует запущенных учётной программы (с логином) и сервиса локального API на том же боксе.
Конкретика доступа — в `docs/erp-api.md` (вне git).

## Перед прогоном

- [ ] Окно с описанием обновления в учётной программе **закрыто**. Пока оно открыто,
      дерево автоматизации пустое (0 узлов против 127), и всё падает с `anchor_missing`.
- [ ] Клиент запущен с рабочим каталогом в его собственной папке. С чужим `cwd` он
      поднимается процессом **без окна** — проверено на двух версиях, ждали 90 с.
- [ ] Секция `Erp` в `dist\host\cli\appsettings.json` заполнена (`build-dist.ps1 -ErpPort … -ErpTokenFile …`).

## Прогон

- [ ] `szcli sz fetch <живая СЗ>` — код 0, в `kb/СЗ/<номер>/` появились `erp.json` и блок
      под маркерами в `запит.md`.
- [ ] Вызов идёт **несколько минут**, и всё это время мышь и клавиатуру трогать нельзя.
- [ ] Состояние учётной программы вернулось: активная вкладка та же, фильтры те же,
      чужие окна документов не закрыты.
- [ ] В выводе есть таблица состава. Если состав пришёл из строк заказа — колонки
      серийников нет, и это правильно: в заказе их не бывает.

## Идемпотентность

- [ ] Дописать в `запит.md` строку руками → повторить фетч → строка на месте, блок
      обновился, маркеры не задвоились.
- [ ] `<sz>.md`: `замовлення` и `пристрій` заполнены. Если `пристрій` пуст — в консоли
      сказано почему.
- [ ] Изменить `пристрій` руками → повторить фетч без `--force` → значение не перебито.
- [ ] Повторить с `--force` → перебито.

## Отказы

- [ ] Учётная программа закрыта → код 4, текст «войди и повтори», а не стектрейс.
- [ ] Ctrl+C посреди вызова → следующий `szcli sz fetch` не упирается в занятость.
- [ ] `szcli sz release` на свободном захвате не роняет команду.
- [ ] Открыть окно обновлений и запустить фетч → код 7 с подсказкой закрыть его.
